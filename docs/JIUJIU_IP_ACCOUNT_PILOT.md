# 九九 IP 号长期运营：首个业务试点

业务输入（用户于 2026-09-24 确认）：目标是做“九九”的 IP 号，长期运营，目标人群 18–35 岁；目前还没有官方账号。项目指向 IP 内容与受众认知，不默认以景区门票收入衡量单条视频，也不把“亲子”当作已确认的主客群。账号名称、平台 ID、权威角色设定、素材权利和实际演出/可拍场景仍待业务确认。

原执行边界（用户于 2026-09-24 确认）：**只做代码与方案，暂不建项目**。用户随后要求持续推进至九九业务可验收；这并未自动提供角色设定、官方账号或真实发布结果，也不等于可以冒充这些事实。关于是否现在创建隔离测试项目，已单独请求确认；确认前不创建“九九”组织、项目、主体或任务。项目 A/B 的测试数据不应被改名成九九成果。

## 后续业务试点步骤（按授权与真实素材逐项执行）

1. 待用户决定启动试点并确认归属后，在测试服建立与 A/B 验收项目隔离的业务项目。首位 Owner 使用已存在的 Windmill 身份，不创建新抖音账号。运维入口见[受控项目初始化](PROJECT_PROVISIONING_V1.md)。
2. 录入“九九”IP 主体和经确认的别名/排除词；没拿到权威设定前，不上传完整剧本或让模型补造世界观。初次外部研究只做少量公开元数据候选，先复核相关性与费用。
3. 从确实相关的公开视频选择至少两条可比案例，人工写出两种内容假设及不同的衡量指标；不足时写“证据不足”，不凑案例数量。
4. 官方账号创建和第一条视频发布后，才录入自有作品与可验证指标；以固定观察窗复盘，明确判为“支持原假设 / 不支持原假设 / 证据不足”，并记录干扰因素。长期运营要有多轮重复或反例，不能凭第一次热度称“方法有效”。

## 验收分层

1. **代码与安全验收**：033 迁移在隔离 PostgreSQL 应用及重放，新增旧卡兼容、事前规则不可改、真实发布凭据不可改、观察窗未到不可复盘；页面可创建、回显和按项目 ACL 拒绝越权。A/B/C 三个真实账号分别登录，不以管理员切换项目代替。
2. **账号建立前业务准备验收**：取得渔岛授权的九九设定与权利摘要，创建隔离项目及主体档案；核对至少两条不同表达形式、与九九目标可比的公开案例，保留来源与反例；形成两种可反驳内容假设，明确指标、对照、观察窗和哪些机制只是推断。未有账号时只能标记“待发布验证”。
3. **首轮实际业务验收**：账号持有人真实发布至少一条有脚本/素材审核版本的作品，登记真实平台作品 ID；依据官方后台或可信运营报表追加一轮带来源的非个人汇总，观察窗届满后锁定快照复盘。只凭一次结果不宣称长期经验有效。
4. **经验复验**：至少第二轮或有意记录的反例，明确什么条件下该机制有效或失效；否则只保留候选假设，不进入可复用经验库。
