# 行动卡绑定主体档案版本（031）

## 业务目的

项目成员把公开视频中的做法转成行动时，必须能回答：当时依据哪一版已核准的主体事实与权利边界。之后即使档案被替换或撤销，历史行动及其复盘不能被悄悄改写。

## 输入与输出

- 输入：本项目已接受且仍可用的公开视频、行动假设/可借鉴点/我方差异、当前项目主体、主体当前核准且权利状态为 `cleared` 的确切档案版本、有效项目负责人。
- 输出：行动卡、不可变的档案版本绑定和审计事件。绑定保存版本号、内容指纹、来源摘要、当时的权利状态与核准时间；项目页只向成员显示已核准摘要、版本及档案当前状态，不返回草稿、来源摘要/引用或审批人。
- `adopt` 由项目 Owner/Admin 创建并必须绑定档案；Researcher 可建 `observe`/`exclude`，两者不绑定档案。旧行动卡保留但标记为“历史未绑定”，不伪装成新规则下的可用行动。

## 接口与协作

- `mutate_project_decision_loop(create_card)` 增加必有的 `profile_id` 字段；采用时为 UUID，观察/排除时为 `null`。同一事务写卡、绑定、审计和幂等回执。后端验证当前项目、角色、视频、主体、档案和负责人。
- 数据库迁移 `031_decision_card_profile_binding.sql` 在提交时强制新采用卡存在绑定，并锁定档案生成快照；跨项目/主体、未核准、权利未核清、更新/删除绑定都失败。
- `get_project_decision_loop` 返回 `approved_profiles` 和每张卡的 `profile_binding`。档案撤销或替换后，旧绑定仍在，页面标出当前失效状态。
- 031 仅记录决策依据。旧 `adopt` 卡的正文、主体、来源和负责人冻结，只允许旧周期的状态/复盘继续。发布登记是事后历史记录；它和 031 都不构成 ASR/L3/素材生成/对外发布的许可。真正的项目级分析或生成必须在执行前重新验证项目归属、当前档案、素材权利、隐私审核与输入指纹。

## 验收与发布边界

1. 从 030 基线升级到 031；旧卡可读，新采用卡无主体/绑定不能提交，同一事务有效绑定能提交。
2. 伪造快照、跨项目/主体、草稿/已撤销/权利未核清档案、非管理者采用、重复或改删绑定均被拒绝；观察/排除仍可用。
3. 档案后来撤销/替换，历史卡仍可读但页面标失效。撤销成员后读写被拒绝。
4. 测试服发布前先备份，并以 `scripts/test-server-release.sh` 核验 031 表、外键、触发器函数体与权限；隔离恢复核对绑定表对象数。迁移与 Raw App 必须在同一发布窗口完成，不能先单独发布新页面。

当前文档描述代码契约；不代表 031 已部署或已在测试服完成业务验收。未创建“九九”业务项目，未触发付费接口。

## 后续：项目级私有 ASR/L3

现有 ASR/L3 是按全局视频运行，项目页故意不复用其原文与审核。下一阶段要新建项目私有审核、转写、L3 执行和成本归属，默认每项目独立审核与调用；接口从 `project_id + video_id + subject/profile version` 建立输入指纹和任务键，执行前再检查项目 ACL、纳入状态、权利与隐私。供应商日账保持账户级实扣，不把它伪造为项目账。MCP 仍只读公开规范化依据，不开放项目私有分析。
