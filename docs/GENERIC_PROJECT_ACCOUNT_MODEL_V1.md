# 多项目、多类型账号的通用关系模型

日期：2026-09-23。状态：业务与权限契约、基础表、领域规则、项目任务及首批项目视频读取 ACL 已在代码中实现；迁移尚未部署，接口尚未接到研究台页面，仍有其他全局读路径未项目化。因此测试服务器并未具备多项目隔离或自有账号授权回流。它补充[通用内容闭环](CONTENT_RESEARCH_CLOSED_LOOP_V1.md)；九九和渔岛只是首批验收样本。

本阶段新增 `021_project_account_foundation.sql`：只创建组织、项目、成员、研究对象、项目账号关系、账号组、跨平台身份链接和授权元数据，不回填或重新归属旧数据；`source_account` 继续保存唯一平台身份。`get_my_projects` 和 `get_project_accounts` 仅以 Windmill 服务端最终用户邮箱查活跃成员，后者只返回该项目的公开账号字段和关系摘要，不读取凭据或授权表。隔离 PostgreSQL 已验证 A/B 项目共享同一公开账号时关系不同且互不可见，撤销成员后立即拒绝。现有研究台的首页、视频库、原始记录、任务执行和 MCP 其他全局查询还没有按项目隔离，故这些新接口暂不发布为多租户能力。

后续 `022_project_task_ownership.sql` 在代码中给研究任务、任务运行与采集运行添加可空项目归属，并以 `project_video_inclusion` 单独记录项目纳入候选的事实；旧记录保持 NULL，不自动归入任何项目。L0/L1 写入校验运行与项目上下文一致，同一公开视频可在两个项目分别纳入且不会复制 canonical 视频。项目任务后端已按最新有效成员记录控制读写，允许项目内协作，撤权后拒绝；原个人任务仍只能由原 owner/allowlist 访问。定时派发仅执行活跃项目/组织的项目任务，且每次实际外部请求前重新检查项目状态（已经发出的请求无法追回），同时保留旧任务行为。项目任务现仅允许 metadata 深度；comments/media 后续链尚无项目归属，调度器和执行器均拒绝这类 scoped 任务，避免误入全局链路。该阶段仍未接入项目化任务创建页面，也未将视频库、原始记录、媒体和模型审核统一接入项目 ACL，故尚未开放多项目使用或部署到测试服务器。

`023_project_video_read_acl.sql` 增加按项目成员和明确纳入记录判断的只读 ACL。视频库、指标时间线和原始记录的项目模式必须先核验服务端最终用户身份，再按项目成员与视频纳入关系过滤；知道 canonical 视频 UUID 不能跨项目读取。未带 `project_id` 的旧数据读取仅对运行端内部读取的 legacy allowlist 开放，不接受调用者自报授权名单，也不因为新项目成员身份而开放。项目模式的通用视频库暂不返回未按项目归属的 ASR/L3 内容；这不是 ASR/L3 已实现项目隔离，而是暂时隐藏。页面项目选择、媒体预览、审核、首页与其他旧接口仍需逐条收口并复测；本阶段不能作为多租户上线依据。

当前 `VideoLibrary.tsx`、`MetricTimeline.tsx` 和 `RawRecordPanel.tsx` 尚未传入 `project_id`，所以现有研究台页面实际仍走 legacy 入口，不会自动触发 023 ACL。三条后端的项目参数仅供后续页面接线与隔离验收使用；在此之前不部署这组改动到测试服务器，也不向普通项目成员开放。项目模式只返回公开视频事实、合并公开指标、公开评论和本项目纳入摘要；全局研究评分、收藏、发现线索、原始 Provider 快照及无项目归属的 ASR/L3 暂时隐藏。

授权记录的 `active` 状态不是调用许可。受控 Provider 必须从 `effective_account_authorization` 解析可用授权，并再次校验调用方项目、用途、字段和操作；该视图同时检查授权、账号关系、项目与组织的实时有效性。关系状态或时间窗发生变化时，既有授权立即撤销；已撤销或过期的授权不能复活，须新建带新证据的授权记录。直接查询 `account_authorization` 的 `status='active'` 不得作为调用依据，因为自然到期不会自动改写状态。

## 当前能力与边界

已实现的 `source_account` 用 `platform + platform_account_id` 统一公开账号身份，账号库能展示公开指标、标签和 `account_type`。但 `account_type` 是账号资料/筛选字段，不是“我方是否拥有、对哪个项目是什么关系、是否已授权”的业务依据。项目任务后端及首批视频读取后端已有项目权限边界，但研究台页面、其他全局接口与 MCP 项目身份映射尚未完成。抖音自有账号的授权数据自动回流仍是 V2 规划。

## 身份、项目、角色与授权分离

| 逻辑对象（拟新增） | 输入和归属 | 输出及约束 |
|---|---|---|
| `organization` / `project` / `project_member` | 业务租户或客户、其下项目、成员和角色、有效期；同一组织可有多个项目 | `organization_id` 是租户边界，`project_id` 是业务数据域；跨组织共享须另有明确授权。Windmill workspace 只是部署/执行环境，不作业务 ACL 主键 |
| `research_subject` | 项目下的景区、IP、角色、商品、活动、品牌、账号等研究对象；可有层级 | 一个项目有多个对象；同一公开对象可被不同项目研究，但各项目的相关性、设定、结论独立 |
| `source_account`（已有） | 平台和平台账号 ID；昵称、认证、账号资料、公开指标 | 平台身份只保存一次，改名不产生新账号；跨平台账号不可仅凭昵称自动合并 |
| `project_account_relation` | `project_id`、`subject_id`（可选）、`source_account_id`、业务关系、目的、证据、置信/核验人、开始/结束时间 | 多对多、可多角色且有有效期；同一账号可在 A 项目为合作方、B 项目为对标，不复制 `source_account` |
| `account_group` | 项目内账号矩阵/活动组合、成员关系及有效期 | 官方号、角色号、门店号、达人号可组成一个矩阵，退出矩阵不删除历史作品或指标 |
| `account_identity_link` | 两个不同平台账号、同一现实主体的证明材料、核验人、有效期与撤销状态 | 经核验的同品牌/人物身份与临时矩阵不是一回事；仅有 verified link 才可做跨平台实体视图，原始指标仍按平台保留 |
| `account_authorization` | `organization_id`、`project_account_relation_id`，或经明确授权的组织级 grant + 逐项目允许名单；平台账号、授权方、用途（读取/分析/发布）、字段/操作 allowlist、有效期、撤销状态和受控 Secret 引用 | 唯一性与生效区间绑定 provider/account/scope/purpose；A 项目获得授权不让 B 项目自动继承。凭据只由受控后端读取，不由账号关系表、Git、前端或共享 MCP 读取 |

“账号类型”拆成三层，不能复用一个自由文本字段：

1. **平台事实**：认证/主体/公开资料，保留来源和抓取时间，不把 Provider 文字当经营关系。
2. **项目关系**：自有官方号、IP/角色号、员工/门店号、受托矩阵号、授权合作达人、未授权合作方、竞品、媒体/参考号、粉丝/UGC 等；配置可扩展，一个账号可同时有多重关系。
3. **任务角色**：发布渠道、传播合作、对标样本、评论观察、销售转化入口等，随项目/活动改变。角色决定页面分组和比较口径，不自动授予 API 权限。

账号的所有权、代运营权、素材使用权、数据读取权、发布权分别记录；达人合作以合同/授权有效期为准。竞品、粉丝与普通样本只用合法可得的公开数据，不因进入“矩阵”获得私有指标。平台官方自有视频数据需要账号授权和权限开通。[抖音官方视频数据接入说明](https://open.douyin.com/platform/resource/docs/ability/open-data/video-data-solution)

## 通用流程与协作

- **建项目**：管理员在业务 organization 下设置项目成员、可见范围和数据保留规则；Windmill workspace 到业务身份的映射单独验收。业务负责人建研究对象，不靠关键词或账号昵称推断身份。
- **挂账号**：研究员提出项目关系，内容/运营负责人核验归属、合作或竞品依据；保留变更历史。对外部创作者不默认视为我方账号。
- **做研究**：发现任务指定项目/对象/账号组；公开 Canonical 数据可复用，相关性、备注、私有素材、L3 与选题只在获授权项目中可见。对标按同平台、账号关系、粉丝量级、内容形式、自然/投流、观察窗分组，不把角色号与竞品达人原始指标直接排名。
- **发布与回流**：一条作品绑定实际发布账号、项目、选题、内容版本和活动入口；同一作品可支持多个对象，但原始播放/成本只记一次，项目视图显示关联及归因方法，不能重复累计为多份业绩。父子研究对象或跨项目总览默认按 distinct 作品/调用去重，而不是求和。自有/授权账号按本项目允许字段回流；其他账号只用公开指标或合作方明确提供的汇总数据。
- **移交/撤权**：员工离职、合作到期、账号易主、授权失效时停止后续同步与发布，历史成果保留可审计但受限资料不再对已撤权成员可见；平台公开身份不因项目解除关系而删除。

## 接口与安全门槛

迁移时不改 `source_account` 的规范化唯一键；新增项目/账号关系和授权状态，不用 `source_account.account_type` 充当 ACL。研究台后端、Windmill runnable 和 MCP 必须用同一项目成员/资料密级策略过滤。现有 MCP 服务 token 没有最终用户到项目成员的映射，不能直接开放项目私有账号、设定或经营数据；默认拒绝，待身份映射真实验收后再开。多平台 Provider 仍按各平台能力和实际授权逐一接入，不因表设计通用就宣称其他平台已上线。

迁移旧数据时，公开 Canonical 账号和视频保持原 ID；旧研究任务、人工标注与审核材料先放进受限的 legacy 作用域并保留原 owner/审计，不自动宣称它们属于渔岛或新客户，也不让新项目成员默认可见。经负责人确认后逐项建立项目关系和相关性。任何迁移回填都须可复核、可回退，不覆盖旧来源事实。

费用账本保留**一次真实外部调用一条记录**；若一次调用服务多个项目，额外分摊/归因记录须有方法与不可变版本，各份额合计 100%，不能把供应商日账重复相加。指标记录来源、时间窗、单位、自然/投流、口径和缺失状态；只有同口径样本可比较。

## 验收样例

用隔离测试数据建立两个项目：渔岛与一个非渔岛项目；在渔岛下建“景区”“螭吻九九”和一个活动/商品对象。绑定至少四种关系：官方景区号、IP/角色号、授权合作达人、竞品/参考号；再让一个公开账号同时关联两个项目且关系不同。验收点：

1. 公开账号身份只有一份；关系、标签和有效期按项目不同，昵称变化不破坏关联，跨平台同名不误合并；有来源证明且人工核验的跨平台身份链接可独立建立、撤销。
2. 项目 A 的私有设定、评论/转写审核正文、后台指标、脚本和成本分摊不出现在项目 B 的页面/MCP；撤权后旧数据仍有审计但成员不能继续读取。
3. 官方/合作账号仅在该项目获准字段、用途和有效期内获取私有指标；A 项目授权不被 B 项目继承，竞品和粉丝号不会触发自有账号接口。授权失效后同步失败关闭。
4. 同一作品支持多个研究对象但不重复计入作品量、播放或供应商实际日账；比较视图显示样本类型与不确定性。
5. 渔岛两个对象和第二项目都能复用任务、证据、决策卡和反馈机制；缺少授权或效果数据时状态为“待验证”，不产生假结论。

真实跨组织项目、外部合作授权和自有账号 API 仍需逐项取得真实资料与权限后现场验收；隔离测试通过不能替代实际授权。
