# 主体档案进入内容决策的下游契约

状态（2026-09-24）：方案及实现门槛，**未实现下游绑定，也未部署 030**。适用于任何项目和主体类型；“九九 IP 号”只是未来的首个业务验收样本。

## 边界与输入

030 的 `research_subject_profile_version` 保存项目内负责人核准的短事实、来源指纹和所申报的权利状态。`approved` 只表示摘要经负责人确认，不表示素材或角色形象已经取得使用许可；`rights_status=cleared` 也不能代替确切素材的授权凭据。现有 029 L1 只消费相关性规则和公开指标，不消费主体档案，**不得给旧分数追加伪造的档案来源**。

下游应区分三种工作：

| 工作 | 输入 | 输出 | 约束 |
|---|---|---|---|
| 研究与筛选 | 项目主体、人工相关性、公开指标 | 可回溯候选与 L1 优先级 | 可以没有档案；不生成创作许可 |
| 内容决策 | 本项目已接纳的公开视频、明确的主体档案版本、人工假设与差异 | 行动卡的不可变档案引用和可见的过期状态 | 不把共享只读视频或别的项目档案升级为本项目证据 |
| 创作、发布及项目语境 L3 | 行动卡、现行已核准档案、确切素材权利凭据、独立隐私审核及输入指纹 | 受控创作/发布记录或项目私有分析 | 对缺失、撤销、替换、指纹错配、权利未清、隐私未审，一律在付费或外发前拒绝 |

## 下一阶段的最小接口

1. 新增项目私有的行动卡档案引用，写入 `project_id`、`decision_card_id`、`subject_id`、`profile_id`、核准时 `content_fingerprint`、`source_digest`、绑定时间和执行策略版本。项目、主体、卡片、档案都由复合外键或数据库约束锁在同一项目；引用不可被原地重写或物理删除。读取只向本项目成员提供核准的短摘要、版本和“当前 / 已替换 / 已撤销”状态，来源引用、来源摘要、审批人和草稿仍限 Owner/Admin。普通成员不得通过共享视频授权读取别的项目的档案。
2. 创建内容行动卡时让负责人选择确切的 `approved` 档案版本；研究型的“观察 / 排除”卡仍可不绑定。任何基于该卡的创作或发布动作须再次核对当前档案和绑定指纹。旧卡可留作历史证据，但档案被撤销或替换后不能继续由旧卡生成新内容。跨刷新、并发变更和幂等重试都必须在数据库侧保持同一判断。
3. 单独建项目作用域的 L3 上下文与结果，不复用全局 `analysis_run` 或全局 ASR/L3 读取权限。若需把主体档案摘要送给模型，发送前应锁定项目和档案状态，核对 `approved`、内容及来源指纹、确切素材的权利凭据、单视频隐私审核和 L3 evidence fingerprint；请求、响应和费用都留存同一组版本号与指纹。任何一项不符须零外部调用、零费用，并可解释原因。
4. 项目采集任务当前不读取档案，不因 030 上线而自动改写查询词或开启评论/ASR/L3。未来若档案字段实质进入采集规则，再把 `profile_id + content_fingerprint + rule_version` 固定到任务输入，并在换版或撤销后标记旧任务待复核。

## 协作和验收

- 内容负责人核对主体事实、禁用表达与素材权利；研究员提出可反驳的借鉴机制；项目 Owner/Admin 决定是否采用并承担档案/作品审核；系统记录版本、权限、费用和每一步的拒绝原因，不代替人工许可。
- 数据库及后端 P0：伪造跨项目 `profile_id`、卡片或 L3 上下文均拒绝；核准后换版/撤销不抹历史但阻止新创作/外发；指纹或权利状态变化在发出 Provider 请求前拒绝；项目分享接收方不能凭分享看到档案来源、媒体或项目 L3。
- 页面 P1：行动卡明确显示引用的档案版本、当前状态与依据；历史版本不能被误标为“仍可用”。保存成功与未知网络结果分开呈现；用户能从原始公开视频和人工依据追溯为什么采纳或排除。
- 业务验收：至少两条真实可比案例形成两种内容假设；一条经过人工素材审核、真实发布、可信自有指标、复盘与规则更新。没有“九九”项目、官方账号、当前设定和发布数据时，只能验收框架，不能宣称内容方法有效。

实现顺序：先完成 030 的跨刷新幂等对账和独立测试；再做行动卡版本绑定及项目 ACL；最后接项目语境 L3 与确切素材权利门禁。每一阶段单独评审、迁移、备份并在测试服验收，不把草稿 PR 当作已上线功能。
