# 渔岛业务使用验收与缺口

日期：2026-09-23。范围：测试研究台的实际使用判断，不是生产发布许可。

进展（2026-09-24）：安全失败诊断已部署，但尚未用新的真实 TikHub 400 复验；原失败原因仍未确定，原任务保持暂停。研究主体/相关性门控和行动复盘结构已随迁移 027–028、研究台及固定版本采集脚本部署到**测试服**，页面已能打开；测试服主体、行动卡和结果观察目前均为 0。它们是可用的业务录入与审核入口，不等于渔岛真实选题和经营效果已验收。项目任务当前仅采公开元数据，项目级 L1 评分、评论/媒体、ASR、L3 尚未接通；没有真实可售产品、客群、有效期、自有发布和经营汇总时，不得宣称形成业务闭环。

## 现场事实

- 创建并激活一次性关键词任务“渔岛选题与对标一次性验证”，近 720 小时、最多 5 条、仅元数据。该任务激活后立即到期；本次通过 Windmill UI 的 `Run now` 触发每小时 dispatcher 一次。TikHub 搜索请求成功，详情 `douyin.app.multi_video_v2` 返回 HTTP 400，运行记为 `failed`，没有自动重试或 LLM 调用。同一批量请求形状曾在其他真实样本成功，当前既无法证明是某条 ID 不可取，也无法证明是接口临时拒绝；失败账本未保留可安全展示的供应商错误码/请求 ID，不应猜测根因。
- 搜索留下的 5 条候选主要是《梦幻西游》“渔岛战队/武神坛”内容，不是秦皇岛渔岛景区的旅游内容。说明仅用同名关键词会污染候选和可能的研判结果；这些记录不得作为景区选题依据。
- 截至北京时间 2026-09-23 14:13，研究台显示该任务“已暂停、下次 —、最近 failed”，避免定时再派发；任务 ID `0ff46e14-89f3-4729-b674-0b4ee718e2cf`，失败运行 ID `8bc1176e-91f2-4d39-b5ad-f2d946034fd3`。这是当时页面/数据库快照，发布前须重新取证。已存在的搜索调用与失败记录留在审计账本；错误请求的最终供应商计费以日账对账为准，本地 `known_zero` 不能代替账单。
- 当时的旧任务写入全局视频/发现资产，5 条同名游戏候选存在污染风险。新建的主体绑定项目任务已在付费详情前加入相关性门控，`pending`/`irrelevant` 不进入项目相关候选/决策队列，也不触发项目 L1/L2/L3；旧全局记录仍保留，不能把新门控误说成已自动清理旧记录或已验证渔岛景区筛选效果。
- 先前的低粉高热、内容充分 ASR→L3、合并数据与原始依据、TikHub 日账和 MCP 只读链路仍保留各自已验收证据；它们不能自动证明“能为渔岛做经营决策”。

## 真正要完成的业务闭环

| 环节 | 输入与协作 | 应有输出 | 验收方式 |
|---|---|---|---|
| 1. 明确问题 | 运营方提供一个具体经营目标、产品/场景、目标客群、可售日期与不可宣传事项；研究员维护任务 | 可追溯的研究问题和有效期，而不是空泛的“找热点” | 任务能说明“为哪个产品、什么日期、回答什么问题” |
| 2. 发现与去歧义 | 景区别名、地理位置、官方账号、竞品账号/区域、排除词；平台公开数据 | 候选先标记景区相关/竞品可比/无关，并注明理由与来源 | “渔岛战队”等同名内容不进入景区候选、榜单或摘要；无关记录可审计 |
| 3. 证据与比较 | 同口径的发布时间、观看/互动快照、内容形式、评论主题和必要的人工核对 | 每条可看原始依据；对标按相似产品、客群、季节与投流条件分组 | 推荐结论能回链至具体视频与时间点；未知投流/转化数据明确标注 |
| 4. 形成行动 | 运营方选定“采用/观察/排除”，指定负责人、素材、发布时机、产品入口与风险约束 | 一张可执行选题卡：假设、可借鉴点、与渔岛不同处、下一步、预期指标 | 不能只生成泛泛总结；每张卡有人负责且能被否决/修改 |
| 5. 结果反馈 | 自有视频 ID、发布日期、渠道、投流成本；按授权或人工导入汇总曝光、点击、预订、核销、退款/投诉等 | 对照事前假设的复盘：内容表现、实际经营效果、混杂因素、下次规则 | 至少一个真实选题完成“研究→发布→经营指标→复盘”；不把点赞等同收入 |
| 6. 持续运营 | 商品库存/价格、开放时段、天气、节假日、活动排期和客服反馈 | 过期建议失效、不可售内容阻断、异常提醒与周/月经验库 | 已售罄、停业或价格变化时不再照旧推荐；费用与失败可追踪 |

## 优先顺序

**P0：先让研究结果可信且可操作。**

1. 定位并复验关键词任务详情 HTTP 400；先补安全诊断：阶段、状态、HTTP 状态、候选数、限长的供应商错误码/请求 ID、账本逻辑调用 ID 和安全重跑条件。诊断不得保存 URL、视频 ID 或响应正文。批量失败后候选只保留为待详情事实，不标成功、不自动拆批重试；确需拆成单条定位时作为新的受控付费诊断执行。失败页不能只显示泛化失败。
2. 已在测试服引入“研究主体/别名/地理上下文/排除词”、任务作用域、`pending/relevant/irrelevant` 相关性状态和人工纠错审计。只有 relevant 候选进入项目相关候选/决策队列；项目级评分、简报、L3 仍未启用，不能把门控实现误说成这些下游能力已完成。下一步用真实渔岛主体规则对同名游戏内容做可审计排除和页面核对，不删除原始证据。
3. 为景区、竞品和自有内容分开建任务/结果视图；支持按产品、场景、客群、日期归档，避免全局视频库混淆研究对象。
4. 采用/观察/排除、负责人、假设、可借鉴点、我方差异、我方发布和按日非个人汇总的复盘入口已在测试服上线。下一步用真实相关样本形成至少一张有依据的行动卡，并以真实发布结果验证复盘；目前 0 张卡、0 条结果，不算业务验收。
5. 建立数据使用边界：记录每个数据源的授权/许可和用途；评论、转写及客服反馈按角色下钻、必要字段脱敏、设置保留/清理期和访问审计；经营汇总导入只收完成决策所需字段，不收游客个人订单。营销声明、画面和音乐授权由指定运营责任人在发布前复核。

**P1：打通效果，才有可复用经验。**

6. 先支持运营方按日/活动导入非个人的汇总经营数据和自有内容数据；字段至少含产品/渠道/日期、曝光/点击/预订/核销/退款/投流支出与可售量。校验口径、币种、去重和数据时区。[抖音官方视频数据](https://open.douyin.com/platform/resource/docs/ability/open-data/video-data-solution)需账号授权；[生活服务商家数据](https://partner.open-douyin.com/docs/resource/zh-CN/local-life/connect/life-open-platform)需接口权限与商家授权，不以 TikHub 的公开视频指标代替自有经营账。
7. 对候选建立可比较基线，发布前记录目标指标、观察窗和对照对象，以及周末节假日、天气、活动、库存和投流条件；复盘时核对实际变化，不对单条爆款做因果归因。关键字段缺失则标记“不可归因”，不得沉淀为可复用规则；形成规则前要求至少有反例或重复样本。
8. 运行层区分“已执行/失败/部分产出/数据过期”，按任务给出下一步；供应商实扣、模型报价估算与未知金额分开。优先让运营看异常与决策，不堆原始接口记录。

**后续能力，不作为当前已完成项。** 其他平台 Provider、商家 API 自动对账、实时库存、多人审批和正式生产告警；只有权限、数据口径与运维责任明确后再接入。原始记录继续保留可下钻，不应成为首页主要阅读负担。

## 最小业务验收试点

选择 **一个真实可售产品或活动、一个明确客群和一个有效时间段**：建立带去歧义条件的研究任务 → 清除本次同名游戏内容对景区视图的影响，并找到目标不少于 10 条经核对相关的自有/竞品/同类素材（数量不足则如实说明，不凑数）→ 对 2–3 个相似案例形成有证据的选题卡 → 发布前核对产品 SKU/价格/库存/营业时间、素材授权和营销表述，预先写明主指标、观察窗、内容版本及对照条件 → 运营方决定采用一条并实际发布 → 关联自有内容与汇总经营结果 → 完成一次带反例、成本和不确定性的复盘。任何阶段若数据不足，就显示“不能判断”或“不可归因”及补证据动作，不生成假结论。

用户需要提供的最小资料是：本轮要推动的产品/活动、官方账号和主要竞品账号、产品有效期/不可宣传信息，以及能否提供不含个人信息的按日汇总经营数据。资料未到位前，仍可先做 P0 的错误定位、去歧义机制和选题卡结构；不得猜测真实售价、库存或转化。

《螭吻九九·神兽觉醒》还需要角色设定与内容创作闭环，不能只套用景区商品漏斗。系统层采用 [通用内容研究闭环](CONTENT_RESEARCH_CLOSED_LOOP_V1.md)，九九作为第一个 [IP/演艺验收样本](JIUJIU_CONTENT_CLOSED_LOOP_V1.md)；不能把数据库和页面做成仅供九九使用。
