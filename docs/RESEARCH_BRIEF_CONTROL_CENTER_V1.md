日期：2026-09-22；现场更新：2026-09-23

测试服务器现状：迁移 020 已执行；研究台已有 4 个任务（1 个周期任务 active、3 个一次性任务 paused），7 条 success 和 1 条 failed 运行记录。新建的“渔岛”任务搜索返回同名游戏内容，详情 HTTP 400 后失败，现已暂停且不再排队；见 [渔岛业务使用验收与缺口](YUDAO_BUSINESS_ACCEPTANCE_V1.md)。每小时 dispatcher 已启用，旧 `scheduled_research_cycle` 已停用；活动周期任务的下一次到点为 2026-09-23 09:05 UTC（北京时间 17:05）。这证明调度可用，但景区业务使用尚未验收。

## 1. 业务目的

研究台不再只靠固定低粉榜计划决定“研究什么”。登录用户可以把一个明确问题保存为研究任务，系统按有限范围自动发现、合并、补充研究材料，并把结果继续放进现有视频库、账号库、热点库和运行成本账本。

研究任务负责控制**采集范围**，不直接替用户得出结论，也不绕过 ASR/L3 的内容审核。

## 2. 输入

V1 支持抖音三类来源：

| 来源 | 用户输入 | 每次上限 | 时间窗 |
|---|---|---:|---|
| 低粉高热榜 | 无 | 5 条 | 24 / 72 / 168 小时 |
| 关键词检索 | 关键词，最长 120 字符 | 20 条 | 24 / 72 / 168 / 720 小时 |
| 指定账号作品 | 公开 `sec_user_id` | 20 条 | 24 / 72 / 168 / 720 小时 |

选择私有媒体或待审核材料深度时，每次候选进一步收紧为最多 5 条，以匹配串行媒体 Worker 和现有媒体批次边界。

共同输入：

- 任务名称；
- 采集深度：元数据、评论、私有媒体、准备人工审核材料；
- 执行频率：单次、每 6 小时、每 12 小时、每 24 小时。

浏览器不提交数据库 Resource、API Key、执行身份、模型、价格或预算值。

## 3. 输出

每次任务执行只返回并保存安全聚合：

- 发现、唯一视频、新候选和评分数量；
- 缓存/未缓存调用数量；
- 估算接口费用及未知价格调用数量；
- 是否继续评论和媒体步骤；
- 任务版本、状态、开始/结束时间和固定错误码。

视频、账号和指标继续进入原有 Canonical 表；同一平台 ID 合并，不为每个任务复制一套孤立数据。Provider 原始响应、Secret、临时下载 URL、评论正文和转写正文不进入任务摘要。

## 4. 接口与执行链

```text
研究台 / 研究任务
  ├─ get_research_briefs（当前登录用户，只读）
  └─ mutate_research_brief（写入白名单 + 登录身份 + 幂等审计）
             ↓
       research_brief
             ↓ 每小时检查，源代码默认 disabled
dispatch_due_research_briefs（最多 5 个）
             ↓
research_brief_cycle(brief_id)
  ├─ run_research_brief：发现 + 详情 + L0/L1
  ├─ process_comment_batch：深度需要时
  ├─ select_cycle_media：深度需要时
  └─ ingest_video_media：串行、私有对象存储
             ↓
      research_brief_run
```

执行器使用服务器固定数据库 Resource、自动化身份和 TikHub Secret。单个发现运行最多 2 次未缓存 TikHub 调用、SDK 零重试；关键词和账号原文不会进入 `source_key`，但会作为任务配置保存在受控数据库中。

## 5. 状态与协作

- `draft`：可编辑，未授权付费采集；
- `active`：已授权按范围调度；
- `paused`：不再调度，可编辑或重新激活；单次任务被领取后也进入该状态；
- `archived`：停止调度并从当前列表隐藏，不删除已采集资产和运行账本。

更新只允许草稿和暂停任务；运行中的任务须先暂停。激活时立即生成一个到期点，周期任务完成领取后以当前时间加周期生成下一次计划，避免系统停机后集中补跑多个旧周期。

## 6. 费用与审核边界

按已核验公开价格，发现阶段的最坏上限为：

- 低粉榜或账号作品：`0.001 + 0.050 = USD 0.051`；
- 关键词：`0.010 + 0.050 = USD 0.060`。

详情只对新候选补齐，缓存命中或无新候选时实际费用可更低。评论按实际新候选另计，媒体下载不把临时签名 URL 持久化。任务激活不设置金额上限，但所有实际调用继续进入调用账本和供应商日账。

无论选择何种深度：

- `auto_submit_asr=false`；
- `auto_submit_l3=false`；
- “准备人工审核材料”只准备评论和私有媒体；
- 用户仍须在内容页实际试听/查看并保存审核，之后才允许 ASR 或 L3 提交。

## 7. MCP 边界

现有 MCP 继续只读查询规范化研究资产。研究任务按登录用户隔离，而测试服务器 MCP 使用服务 token，目前没有经过验收的“最终用户身份 → 任务 owner”映射，因此 V1 不把任务增删改或任务列表直接暴露给 MCP；不能为了方便把全部用户任务暴露给共享 token。
