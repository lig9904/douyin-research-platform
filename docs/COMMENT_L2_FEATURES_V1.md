# 评论证据 L2 确定性特征 V1.1

日期：2026-09-19

## 目标

把已经落入自有 Evidence Dataset 的评论与回复，转换为可复现、可版本化的 L2 特征快照。

本步骤：

- 不访问 TikHub
- 不调用 LLM
- 不做情绪、立场、受众画像或因果推断
- 不把评论样本冒充全部评论或全部受众
- 不把缺失值补成 0
- 不在特征快照中保存高频词、短语或原始文本

规则版本：`comment-features-v1.1.0`。

## 基础快照字段

每个视频、规则版本和证据指纹对应一个不可变快照：

- 采样评论总数
- 根评论数
- 采样回复数
- 来源 observation 数
- 非空文本数
- 含问号文本数
- 点赞数已知样本数、合计、中位数
- 回复数已知样本数、合计、中位数
- 非空文本平均 Unicode code point 长度
- Provider 与 sample_reason 的聚合计数

原始评论 ID、文本、请求 ID、cursor、raw_ref 不进入快照 metadata。

## V1.1 文本分布与规则信号

文本先做 Unicode NFKC、转小写和连续空白折叠。快照只保存以下聚合值：

- 规范化后的唯一文本数
- 重复文本数、重复组数、最大重复组大小
- URL、@提及、纯 emoji/符号、连续重复字符、单个字母或数字文本的数量
- 模板样文本数
- 可进入字符二元组分布的文本数
- 字符二元组总数、唯一数、最高频次数和最高频占比

模板样信号是显式规则，不是语义分类。满足任一条件即计入：规范化文本重复、含 URL、只有 emoji/符号、同一非空白字符连续至少 4 次。@提及仅单独计数，不会单独触发模板样判定。

字符二元组仅使用 Unicode 字母和数字；计算前移除 @提及。URL、纯 emoji/符号、连续重复字符以及少于 2 个字母或数字的文本不进入该分布。系统不保存最高频二元组的文本，只保存次数与占比，因此不能从快照还原评论内容。

当没有可计算的字符二元组时，最高频占比为 `NULL`，不是 0。历史 v1.0 快照新增字段也保持 `NULL`，不会伪造为已观测到的 0。

## NULL 与 0

`like_known_count` 和 `reply_known_count` 单独记录覆盖度。

- 所有点赞数均缺失：`like_sum=NULL`、`like_median=NULL`
- 点赞数明确为 0：保留为 `0`
- 所有回复数均缺失：对应聚合为 `NULL`
- 回复数明确为 0：保留为 `0`

因此下游不会把“接口没给数据”误解释成“真实为零”。

## 幂等与版本

证据指纹由稳定排序后的评论证据及 observation keys 计算。相同证据重跑复用同一快照；新增原始响应 observation 或指标变化会生成新快照。

快照成功后，视频 `research_level` 最低提升到 L2。这里表示“已形成 L2 证据特征”，不表示内容质量高，也不表示已得出语义结论。

## 解释边界

这些计数只描述已采集样本，不能推出：

- 全部评论中的真实比例
- 全部观众的态度或人口属性
- 评论与传播效果之间的因果关系
- 某条评论是否由机器人或营销账号发布

后续主题聚类或语义分析必须另行版本化，并只对明确晋级的小样本运行。
