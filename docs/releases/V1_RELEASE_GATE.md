## 已核验输入与输出

- 研究任务输入：登录用户可定义低粉榜、关键词、指定账号范围，选择单次或 6/12/24 小时和采集深度；服务器每次发现最多 2 次未缓存 TikHub 调用，ASR/L3 不自动提交。
- 研究资产输出：视频库合并指标，保留来源、快照和按需原始记录；内容充分的真实样本已经从私有媒体、人工音频审核、ASR、人工正文审核走到 L3 页面。
- 费用输出：TikHub 供应商日账单独显示并标账期、范围和未终账；本地调用报价估算不冒充实扣；ASR 金额未知明确显示待对账，部分已知金额也不被吞掉。
- 接口与协作：研究任务由登录用户在研究台管理；Codex 通过十项受控只读 MCP 工具查询已入库规范化资产，不获得共享 token 下的用户任务写权限或原始敏感正文。
- 运维：测试服务器隔离数据库恢复、MinIO 单对象丢失恢复、ASR 进程失败恢复及 Raw App 双向回滚均有现场证据；应用服务器不运行 Nginx。

## 用户验收动作

仅走通“研究任务 → 视频库合并结果 → 原始依据 → 已审核分析 → 运行与成本每日账”还不够。需按 [渔岛业务验收](../YUDAO_BUSINESS_ACCEPTANCE_V1.md) 修复关键词错配与详情失败，隔离本次已入全局资产的无关候选，证明真正进入景区结论的素材相关；明确评论、转写与经营汇总的授权、角色权限及保留边界；发布前核对可售状态、素材授权和事前评价指标；形成有证据、可执行的选题并关联一次真实经营结果复盘。资料不足时如实显示不能判断或不可归因。未经业务验收及用户确认不发布正式 V1。

内容闭环的产品设计应按[通用研究对象模型](../CONTENT_RESEARCH_CLOSED_LOOP_V1.md)实现；[IP 试点](../JIUJIU_CONTENT_CLOSED_LOOP_V1.md)是一个验收样本，另用一个景区商品或活动对象验证通用性。两类对象的证据、权限、L3 和效果不得串用。模型与业务复盘须分别依据当前部署和实际运行证据验收，不能因设计文档合并而宣称 V1 已通过。

“能用于其他项目和其他类型账号”还需按[通用账号关系模型](../GENERIC_PROJECT_ACCOUNT_MODEL_V1.md)完成跨项目隔离、账号多角色、授权边界和去重验收。现有全局账号库只是数据底座，不能因拥有 `account_type` 字段就宣称多项目/多类型账号业务能力已生效。
