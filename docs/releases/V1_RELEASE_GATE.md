# V1 正式发布门槛与范围

状态：2026-09-23 测试服务器已有多项技术核验；渔岛实际试跑暴露关键词错配和详情 HTTP 400，业务验收未通过，**尚未创建正式版本标签**。

## 已核验输入与输出

- 研究任务输入：登录用户可定义低粉榜、关键词、指定账号范围，选择单次或 6/12/24 小时和采集深度；服务器每次发现最多 2 次未缓存 TikHub 调用，ASR/L3 不自动提交。
- 研究资产输出：视频库合并指标，保留来源、快照和按需原始记录；内容充分的真实样本已经从私有媒体、人工音频审核、ASR、人工正文审核走到 L3 页面。
- 费用输出：TikHub 供应商日账单独显示并标账期、范围和未终账；本地调用报价估算不冒充实扣；ASR 金额未知明确显示待对账，部分已知金额也不被吞掉。
- 接口与协作：研究任务由登录用户在研究台管理；Codex 通过十项受控只读 MCP 工具查询已入库规范化资产，不获得共享 token 下的用户任务写权限或原始敏感正文。
- 运维：测试服务器隔离数据库恢复、MinIO 单对象丢失恢复、ASR 进程失败恢复及 Raw App 双向回滚均有现场证据；应用服务器不运行 Nginx。

## 用户验收动作

仅走通“研究任务 → 视频库合并结果 → 原始依据 → 已审核分析 → 运行与成本每日账”还不够。需按 [渔岛业务验收](../YUDAO_BUSINESS_ACCEPTANCE_V1.md) 修复关键词错配与详情失败，隔离本次已入全局资产的无关候选，证明真正进入景区结论的素材相关；明确评论、转写与经营汇总的授权、角色权限及保留边界；发布前核对可售状态、素材授权和事前评价指标；形成有证据、可执行的选题并关联一次真实经营结果复盘。资料不足时如实显示不能判断或不可归因。未经业务验收及用户确认不发布正式 V1。

内容闭环的产品设计应按[通用研究对象模型](../CONTENT_RESEARCH_CLOSED_LOOP_V1.md)实现；[螭吻九九](../JIUJIU_CONTENT_CLOSED_LOOP_V1.md)是首个 IP/演艺样本，另用一个景区商品或活动对象验证通用性。两类对象的证据、权限、L3 和效果不得串用。上述新增模型、人工经营数据回填与业务复盘尚未实现，不能因设计文档合并而宣称 V1 已通过。

## 发布前复核

1. 将验收反馈与测试服务器应用版本、数据库迁移、计划启用状态和代码提交绑定记录。
2. 确认目标提交的 provider-tests、web-dashboard 和外部反代/部署 CI；仅检查实际触发的工作流，缺少的按同一提交补跑。
3. 复核 GitHub 开放 Issue；未完成项在正式说明中列为延期，不把“已实现”写成“已部署”或“已验收”。
4. 从已验收的主线提交创建首个稳定版本，更新 Python、MCP 和 Web 版本元数据及 README，再由 GitHub CI 通过后发布不可变标签和 Release。测试服务器发布记录不等于生产部署。

## 已知边界与后续

- 火山 ASR 实扣与按天账单自动读取尚未接通；L3 目前是报价估算。不能把未知费用标为 0。
- 2026-09-22 有一条旧固定媒体链路 `media_download_failed`，零新增付费调用，需继续监控与定位；不掩盖既有成功样本。
- TikHub 当前账期为累计、未终账；更广泛的接口准确性/私密映射仍属于 Issue #1 的长期核验。
- 测试服务器不是生产：异机灾备、真实多账号成员 ACL、外部告警闭环和其他平台 Provider 不由本次 V1 测试声称完成。
