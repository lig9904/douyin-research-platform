# 九九项目：账号粉丝核验与项目费用口径

日期：2026-09-27。状态：代码与隔离 PostgreSQL 回归、GitHub CI 通过；**已发布测试服，并完成两次真实 TikHub 账号接口调用与一次缓存复用验收**。本文件不包含密钥、原始私有内容或供应商返回全文。

## 输入与输出

- 输入是某项目中已 `accepted` 的 1–10 个精确抖音视频 ID。系统先从含该视频 ID 的原始 TikHub 视频响应重新解析作者 `sec_uid`，并与精确视频 ID、项目纳入关系、当前账号 ID 逐项比对；仅作原始响应候选的文本检索本身不构成放行证据。只有 UID、没有 `sec_uid` 的视频在付费调用前拒绝。
- 对同一稳定账号在单次运行内去重，并通过账号级数据库锁串行化跨运行的缓存判断。未命中缓存才发起单次 REST 请求；付费请求期间锁定项目、组织、视频纳入关系及账号，撤销先提交则拒绝调用，调用先获准则并发撤销等待完成。
- TikHub `douyin.app.user_profile` 返回的账号身份必须与请求 `sec_user_id` 完全相同。成功响应保留原始记录，另写一条带原始记录引用的账号粉丝快照；不改写原视频的零值。30 天内经身份核验的快照优先用于视频库、账号库、项目账号矩阵的合并粉丝数；原始值和字段来源仍可核查。核验得到真实 0 时页面显示 0，不再误标“待核”。
- 任务流水与每次 Provider 调用以 `pipeline_run_id`、`project_id` 关联。未缓存的成功调用按接口目录基础价 USD 0.001/次记**估算**，不是 TikHub 实扣；缓存命中没有新外部调用。部分失败保留已知报价小计和未知调用数，项目日账显示部分报价并标记未闭合，不把未知费用当零。供应商日账仍按账户实扣另行核对。

## 接口、协作与验收

受控入口是 `refresh_project_account_profiles` 服务函数与研究台视频详情中的“刷新公开账号资料”按钮；后端只信任 Windmill 的 `WM_END_USER_EMAIL`，在预览和执行时核验当前项目 Owner/Admin、已接受的视频与原始 `sec_uid` 证据。预览不读 TikHub Secret、也不发外部请求；点击付费确认后再次检查身份和项目状态，单次最多一个新请求。按钮仅出现在已接受的抖音项目视频详情，不放入通用配置页。页面回报新请求数、缓存命中数与快照数，并将价格明确标为基础估算、实扣待日账核对。

新 App runnable 的依赖锁由 `uv pip compile` 对固定 Git 提交和 Python 3.14 解析生成，再由官方 Windmill `generate-metadata rehash` 离线刷新应用哈希。测试工作区的仅 App 写入令牌无法执行 Windmill 在线依赖解析（需要额外 `jobs:run`）；失败生成的多余 YAML 已撤回，没有为了锁解析扩大该令牌权限。测试服真实运行已核对该锁能够安装并完成入口任务。

测试服只读预检：两条已接受对照视频 `7658347686323555610`、`7681244536475077934` 各有 TikHub `douyin.app.one_video` 原始响应；原始 `data.aweme_detail.aweme_id` 与视频 ID 精确一致、`data.aweme_detail.author.sec_uid` 与规范账号 ID 精确一致，分别查到 2 条与 1 条匹配响应。原先试图连接 `discovery_event.metadata.request_fingerprint` 与 Provider 响应指纹，两视频均为 0；两者并非同一指纹，因此已改用候选原始响应再规范化逐项验证。

测试服发布与实呼验收：服务器代码切至提交 `400866d2caea87f8cd2b3b5b7a1ddbcb9f164511`；Windmill 单个 Raw App 的版本由 66 增至 67，发布前版本 JSON 已保存于服务器 `/srv/douyin-research-test/backups/jiujiu-profile-before-app-v66-20260927.json`。发布前该接口的外呼、任务、账号快照计数均为 0。研究台以“九九 IP 号”项目打开两条已接受视频，各通过页面确认发起一次 `douyin.app.user_profile` 请求；独立回读得到 2 条外部调用、2 条成功项目任务、2 条账号快照，账号粉丝分别为 1,755 与 25,237，页面同步显示。两个成功任务各记 USD 0.001 **估算**。对第二账号再点一次刷新后，页面显示“新增请求 0、缓存命中 1、保存快照 0”，数据库仍只有 2 条外部调用、2 条快照，新增第三条成功任务的金额为 USD 0。项目“运行与成本”在上海自然日 2026-09-27 列出 3 次账号核验、已知估算合计 USD 0.002；TikHub 实扣日账尚未对齐，不能称为实际消费。

隔离 PostgreSQL 覆盖：同账号去重、缓存零外呼、身份错配拒绝、UID-only 零外呼、原始响应绑定与幂等、项目撤销锁、同账号并发锁、部分失败费用小计、原账号其他指标保留、项目与全局页面粉丝优先级。前端 bundle 与仓库全量测试通过。测试服实呼证明了这两条视频的账号核验链路，但**不等于**供应商实扣对账或九九内容方向已可验收。

## 对九九业务判断的边界

账号粉丝核验可以修复“视频详情粉丝 0、互动却不为 0”带来的分层误判；仍不能修复两个角色短片的播放量 0、缺完播/留存、缺完整视听审片和目标观众盲看。下一阶段不能仅按点赞或评论挑创作方向：先完整核看可比视频及相邻集，再以统一问题让 18–35 岁观众复述角色、冲突与追更意愿，并保留反例。只有指标来源与内容理解两条证据均足够，才能形成可执行的九九选题/制作建议。
