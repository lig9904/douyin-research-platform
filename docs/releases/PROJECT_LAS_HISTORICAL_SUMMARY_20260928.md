## 输入、绑定和交付

- 输入是四条原始 Windmill 完成作业的 JSON 与此前私有收据清单。每条须同时匹配视频 ID、供应商任务号、作业号、原始结果 SHA-256、正文 SHA-256、token 用量及现有项目收据。
- `scripts/import-las-historical-summaries.py` 默认只做事务回滚的预演；`--apply` 仅向项目私有 `project_las_analysis_result` 写入机器正文，不改收据、账单、人工案例状态或模型授权。同内容重放跳过，冲突内容拒绝。
- 四条已于测试服回填，合计 30,976 字、19 个机器时间段事件（依次 5、3、6、5）。首轮预演 `inserted=4 skipped=0`，正式写入同数；重放预演 `inserted=0 skipped=4`。数据库独立回读为 4 条结果、4 个不同正文哈希，完整人工 Case 仍为 0。
- 写前、写后分别完成测试服 PostgreSQL/Windmill 备份：`20260927T220613Z`、`20260927T220857Z`。本次不涉及数据库迁移或 Raw App 发布。

## 用户页面与使用边界

测试研究台“视频库”中，进入[小钻风第 6 集](https://www.douyin.com/video/7662998648669752619)的“本项目整片音画分析”，展开“历史回填 · 已完成”，已实际读到机器整片观察和 `0:00–2:00` 的五段时间码事件；原始机器输出也可在该区域按需展开。其余三条已在项目私有结果表回读，尚未逐条做页面人工点击验收。

这批正文可用于定位需核看的人物行动、叙事节点和反证，但它不是人工完整看听，不证明某种桥段会提高播放量，也不解锁“采用”行动卡。页面明确提示历史任务没有本项目整片审核绑定。供应商实际扣费仍待账单对账；原四笔只是 token 估价，不能用本次无新调用代替历史实扣。
