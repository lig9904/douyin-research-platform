## 业务输入、输出与协作

- 项目负责人在研究台打开已接受的私有完整视频。后端从对象存储读取**实际字节**，核对数据库 SHA-256、长度、媒体类型及返回的具体 S3 `VersionId`，再给前端一个只指向该版本的 5 分钟 HTTPS 播放链接。页面展示对象版本和审核指纹；仅播放事件加人工确认可以保存审核，不能以自动播放视为看完整片。
- 保存审核时，后端按负责人确认的同一 `VersionId` 再读一次字节，校验项目/资产未变，持久保存 `versioned_bytes_v2` 和对象版本。审核版本不可改写；旧 041 审核只作历史记录，不得新建付费任务。项目负责人另点“启动一次分析”才生成 `prepared`；不因页面预览自动付费。
- 可信 Worker 在认领前再次读取审核指定版本的全部字节，校验 SHA-256/长度/类型，并在供应商 URL 中签入同一 `VersionId`。认领事务提交后只 Submit 一次；Poll 使用原供应商任务号，完成凭证保留相同对象版本。普通成员仍只能按项目 ACL 看获准结果，不能复用另一个项目的审核。

## 2026-09-27 旧业务对象现场只读核验

在测试研究台选中项目 A 的已接受视频，整片资产对应测试桶中的内容寻址对象。AIStor 控制台可见对象约 22 MiB、写入时间早于桶 Versioning 启用；对象选单的“显示对象版本”不可用。为排除界面推断，使用既有测试存储变量执行只读脚本：完整流式读取 `23,318,765` 字节，重算 SHA-256 与内容寻址键一致，但 S3 `GetObject` 的具体 `VersionId` 为 `null`。脚本不返回媒体字节、密钥或签名 URL，未调用 LAS、未覆写对象。完整对象键和作业引用保留在受控测试服记录。

结论：该对象为版本控制启用前的遗留版本，不能仅凭桶现已启用 Versioning 就让它通过 042 审核。要验收这条视频，必须先在**隔离对象**验证同键条件写入、旧版保留、当前版本读取及签名下载，再对业务对象制定明确的写入/回退方案并获准执行；不能直接把 `null` 伪造为具体 VersionId。

## 2026-09-27 隔离对象同内容提升验证

按用户批准的隔离验证范围，只对一个 33 B 隔离对象执行一次 `If-Match` 条件写入。写入前核对最新对象确为已知第二版且字节、长度、SHA-256 不变；写入体和原最新版本完全相同。AIStor 返回新的具体 VersionId；随后重新读取当前版本、新版本和前两个旧版本，旧版摘要均未变化，新版经公网 HTTPS 预签名 GET 返回 200 且字节一致。精确作业、对象键和版本保留在受控测试记录。脚本没有返回凭据、签名 URL 或对象内容。它是一次性探针：最新 VersionId 改变后，再运行写入参数会在写前拒绝。

这证明测试桶当前支持“同键、同内容、条件写入产生可核验的具体版本”，**不等于已经提升业务视频**。业务视频约 22.2 MiB；正式处理前应先锁定项目资产引用与原 SHA-256/长度/类型，完整读取并复算当前 `null` 版，记录 ETag，使用 `If-Match` 原样写入，再核对返回的具体 VersionId、最新版本字节、旧 `null` 版可读性及签名下载。任何条件失败都应停止，不换成无条件覆盖或自动重复写入；写入结果不明时先只读检查最新版本与版本列表，避免多造版本。数据库业务资产不改键或改 SHA-256，审核仍由负责人重新完整核看。该段是隔离探针当时的结论；后续用户已批准测试服发布及业务对象写入，实际结果在下方逐项记录。

业务视频的额外只读作业再次完整校验了 `23,318,765` 字节，并以明确的 `VersionId=null` 读取旧版，所得 SHA-256 与内容寻址键相同（`null_version_readable=true`）。这证明在当前 IAM 下旧 `null` 版**写前可读**；写后是否仍保留、签名读取是否正常，仍需在获准的业务对象操作中现场核验，不能由这次只读检查代替。精确作业定位留在受控测试记录。版本提升函数的写后检查现还逐项核对完整自定义元数据及原有缓存/下载头；丢失任一项会标记结果待人工核查，不能自动重试。

## 迁移操作新增门槛与独立复审

独立代码复审指出：`If-Match` 只绑定 ETag，不会原子锁定桶的 Versioning 状态；若管理员在状态检查后暂停 Versioning，同键 PutObject 仍有覆写旧 `null` 版的风险。故业务对象操作前必须冻结该桶的配置变更并确认没有其他同键写入者，备份旧对象及其元数据；写入结果不明时只读排查，不能自动重试。代码中的两次 `GetBucketVersioning` 是必要的写前拒绝门槛，但**不能替代外部变更冻结**。

两次只读作业分别证实：当时的测试媒体凭证对 `GetBucketVersioning` 返回 `AccessDenied`；对象的 SHA 元数据匹配、无显式服务端加密/对象锁/非标准存储类别/到期标志，但 `GetObjectTagging` 同样返回 `AccessDenied`，所以**当时不能断言对象没有标签**。精确作业定位留在受控测试记录。真实提升在这两个只读能力得到核验前应写前失败，不使用管理员控制台的可见状态代替同一执行身份的权限证明。已加入 `promote_legacy_null_version` 显式操作原语：要求具体 ETag、完整字节校验、当前/历史 `null` 版可读、Versioning Enabled、无标签及不支持的对象属性，条件写入后再核验新旧版本；本地假 S3 回归在现场业务操作前通过，随后实际结果见下方记录。

经用户批准，仅在测试桶现有桶专用策略补充 `s3:GetBucketVersioning`（桶 ARN）和 `s3:GetObjectTagging`（该桶对象 ARN），原有权限保留。起初试加 `s3:GetObjectVersionTagging` 后，只证明桶状态可读，对旧 `VersionId=null` 的标签请求仍为 `AccessDenied`；随即以 `s3:GetObjectTagging` **替换**该项，没有叠加第三项权限。同一测试媒体 Key 的只读作业返回 `bucket_versioning_status=Enabled`、`tag_count=0`、`tagging_error=null`、`null_version_readable=true`，真实视频字节数和 SHA-256 保持不变。另一项零写入作业对隔离对象的具体版本执行 `GetObjectTagging`，返回 0 个标签；同一权限满足旧 `null` 版写前检查和新具体版写后检查。精确作业和版本留在受控测试记录。两次任务都未改写真实视频、未调用 LAS。此处权限缺口已消除；业务对象操作仍以实际备份和执行当刻的冻结/身份/指纹检查为门槛。

收到重复授权回复后，2026-09-27 再次回读并恢复了上述两项最小权限配置（未保留额外的 `s3:GetObjectVersionTagging`）。同一测试媒体 Key 的只读作业重新完整读取业务视频 `23,318,765` 字节，返回 `sha256_matches=true`、`bucket_versioning_status=Enabled`、`bucket_versioning_error=null`、`tag_count=0`、`tagging_error=null`、`null_version_readable=true`；对象仍是 `null` 版本，本次没有对象写入或 LAS 调用。精确作业定位保留在受控测试记录。

当时的单对象操作入口不属于 042 成组发布目标，而是在 042 发布后**单独发布**。现场数据库只读联表确认：该 SHA 对应唯一视频资产，且在验收项目 A、B 均为 `accepted`；入口仅绑定项目 A 的精确资产。默认调用只做数据库及对象 HEAD 检查。用户后续已明确确认测试服发布与同键同内容条件写入；操作入口增加分离的桶内备份作业：使用 `If-None-Match: *` 新建备份 Key，逐字节和元数据核验具体版本。提升作业在再次读回这份实际备份及旧 `null` 版后，才调用无客户端重试的 `promote_legacy_null_version` 一次。两次作业均要求管理员身份、完整 SHA、原 ETag 和桶配置/同键写入冻结；任何不确定结果都先只读核查，禁止自动重跑。
