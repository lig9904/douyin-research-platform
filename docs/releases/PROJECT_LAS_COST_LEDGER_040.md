# 040：项目 LAS 整片任务与费用凭证

状态：代码与本机隔离验证、测试服 040 迁移、隔离恢复、四条历史任务回填，以及研究台新版页面发布和回读已完成；供应商实扣核验尚未完成。此文不是供应商账单验收记录。

## 业务输入与输出

- 输入：项目已接受且仍可用的公开视频、已存视频对象及 SHA-256、逐次付费调用的授权来源、供应商任务号、提交与完成作业号、模型和算子版本、用量与执行时间。
- 输出：项目成员可见的 LAS 逐任务凭证、按上海任务执行日的估价和未知项，以及按供应商账单日、时区、账户分别列出的已登记分笔。不同币种不折算；估价与分笔金额不相加。
- 机器整片分析不写成 Case 的人工核片结论，不自动把 `partial` 案例升为 `complete`，也不代替人工剧情、反证与适用边界审核。

## 接口与协作

`040_project_las_analysis_receipt.sql` 新增调用尝试、不可变结果凭证和独立账单分笔。未来线上调度必须先持久写入 `live_pre_dispatch/prepared`，在调用前原子标记 `submitting`；回包丢失时保留 `unknown` 尝试并按供应商任务号回查，不能自动重发付费请求。当前提交**没有**把这套状态机接入线上 LAS 调度，不能宣称未来调用均已防漏账。

2026-09-27 追加了固定算子/模板/模型的 `VolcengineLASProvider` 传输适配层及离线契约测试（提交 `669c01d`）：一次 Submit、同任务号 Poll、拒绝重定向、严格回包与终态用量校验。它没有项目审核、040 持久认领、可信 MinIO URL 签发或 Windmill 调度入口，因此**尚未启用线上实时 LAS 调用**；任何 Submit 后异常都不得自动重提。

`scripts/import-las-trial-receipts.py` 只导入人工核对过的历史测试作业，默认事务回滚预演，`--apply` 才提交；检查项目最新 Owner/Admin、接受状态、视频资产指纹、提交与完成身份和重放一致性。私有清单不入 Git。它不导入账单，也不证明供应商实扣。

`get_project_daily_cost` 按项目 ACL 查询，研究台“运行与成本”显示任务估价、未闭合尝试和分笔登记。表中即使出现 `final` 字段，在尚无受控供应商账单导入与来源核验流程前，页面仍标“来源待核”，LAS 任务仍算待对账。其他 ASR/L3 任务原有的 `actual` 仅为任务自报口径，并非供应商分笔实扣。

## 火山实际日账的可获得口径（待实账验证）

火山[费用中心 OpenAPI 索引](https://www.volcengine.com/docs/6269/1165275?lang=zh)列出 `ListBillDetail`（账单明细）、`ListBill`（账单）和 `ListSplitBillDetail`（分账账单）。应先从登录账户的费用中心取得一日真实账单明细，核对其产品名、账号、账单日、结算币种、实际金额字段与是否已出账，再决定用相同条件调用 `ListBillDetail` 定时拉取。**当前只有接口文档，没有本账户的 API 响应或导出文件，故未接通日账，也没有把 0.966 CNY 估价升级为实额。** LAS 调用 Key 不等于费用中心的账单读取凭证；账单只读身份与权限须单独验证，不能复用供应商任务 Key 猜测调用。

2026-09-27 已在登录账户的费用中心只读核对：九月账单总览与“账单流水”有账户级月度应付和现金支付汇总；流水能看到按北京时间标注的消费时间和产品，但不能据此直接把某行绑定到 LAS 任务。切到“账单明细 → 按天”并选 9 月 26 日、27 日，页面的筛选合计均显示 0，同时表格仍留有其他日期的产品行；页面还明确提示当月数据可能延迟出账、结果仅供参考。故这些 0 不能解释为 LAS 免费或两天零消费，也不能作为日账验收。原始账户标识和具体总额仅保留在本机忽略目录的私有核查记录，不进入公开仓库。

同日再次在已登录账户筛选“账单明细 → 计费项 → 按天”，将日期起止均设为 2026-09-27，并将产品设为“字节跳动大模型服务（豆包大模型）”：表格显示“暂无内容”，筛选合计未给出金额。此筛选只覆盖该产品，不能推断 LAS 或火山账户全产品消费为零；041 仍无可核验的供应商实扣分笔。

研究台“运行与成本”已补上按供应商区分的缺失提示：即使 TikHub 有记录，只要当前列表没有 `volcengine-billing` 行，就明确显示火山实账未出现在当前查询范围，不能把其他供应商的 `available` 借作火山已同步。账期标签改为仅表示当前/历史，终账状态由独立标签表达，避免历史终账行同时显示“未终账”。这只是展示修正，不代表火山签名 transport、日账数据或 041 实扣已接通。

展示修正提交 `4aafdf9` 的 GitHub build/test/validate 全部通过；用已授权的测试工作区应用发布身份只推送 `f/content_research/research_dashboard`，远端单个 Raw App 版本数从 65 增至 66。浏览器重新打开项目“九九 IP 号”的“运行与成本”后，原有 LAS 四条历史任务和 ¥0.966 估价仍可见，分笔表仍明确显示暂无登记。本账号当前应用仅列项目范围，无法进入管理员历史运行台；因此新火山缺失提示与终账标签虽经组件测试、前端打包及单应用发布，**尚无该管理员页面的现场可见验收**。

日账展示拟采用“火山账户 × 账单日 × 结算币种 × 产品”的已出账金额，并另列未出账/待对账状态；用户可看到一天的供应商账单总额，但它不能凭空拆成每个项目或任务的实际费用。按任务写入 `project_las_supplier_bill_item` 仍须有能绑定供应商任务号或账单明细号的证据。火山[账单管理说明](https://www.volcengine.com/docs/6269/94010?lang=zh)指出账单可能延迟生成，账单明细精度与账户实际扣款精度也不同；现金[收支明细](https://docs.volcengine.com/docs/BillingCenter/Incomeandexpendituredetails?lang=zh)还包含充值、退款等交易，所以“账单日消费”不能标成“当日现金扣款”。

如要按火山项目或标签分账，[`ListSplitBillDetail`](https://docs.volcengine.com/docs/BillingCenter/ListSplitBillDetail-PageQuerySplitBill?lang=zh)支持 `BillPeriod`、`ExpenseDate`、`GroupPeriod=1` 的按日查询及结算币种金额，但官方注明它比原账单明细晚约两天。该接口适合之后核对分账，不适合冒充实时日消费。首次实账验收须以同一日期的费用中心页面/导出、API 分页结果和账户标识三者对照，并记录出账延迟；页面在无账单行时显示“尚未出账/待核”，不得显示 0 元。
