# 032 项目私有 ASR/L3 业务验收清单

状态：代码候选；未发布测试服，未执行项目私有付费链路。031 数据库已迁移，但 Raw App 仍为 030（见 `TEST_SERVER_031_20260924.md`）。本文件不把本地 Mock、全局历史案例或迁移成功写成项目验收。

## 要解决的业务问题

同一公开视频可能被不同项目研究。项目 A 的音频审核、转写、L3 正文审核、分析结论和费用属于 A；项目 B 不应仅因拥有同一视频就看到或复用这些内容。负责人需要能从视频原始依据看到研究结论，判断能否借鉴，并知道当天项目任务的已知费用和待对账项。

| 模块 | 输入 | 输出与边界 | 协作/验收 |
| --- | --- | --- | --- |
| 采集和媒体 | 已纳入并 accepted 的公开视频、真实规范化 WAV | 媒体存在私有对象存储；项目页仅显示有权限资产清单及短期试听 URL，不返回对象 Key | 负责人试听完整音频；确认有充分人声及具体价值，拒绝空泛样本 |
| 项目 ASR 审核 | 指定资产的完整 manifest、服务域名、固定同意语 | 只写该项目人工审核；撤销后不得新提交或继续传播 | 登录用户亲自确认，不能由定时 Worker 自批 |
| 项目 ASR 执行 | 当前审核 ID、受信任存储与火山配置 | 同一任务 Key 最多提交一次；后续只轮询原任务；转写、状态和费用仅写项目表 | 真正调用火山，核对请求标识、音频可取、时长、文本、分段；中断后恢复轮询不重付费 |
| 项目 L3 审核与分析 | 完整转写、公开视频元数据、评论数字统计 | 人工确认固定指纹后调用方舟；不发送评论原文；结果只写该项目 | 人工检查钩子、叙事结构、可借鉴机制、局限，不把模型推断当事实 |
| 页面与决策 | A/B 同视频，项目成员角色 | A 看 A 的内容和费用；B 不见 A 的私有证据；负责人可追原始视频、指标、转写和输出 | 以 A/B/C 登录实际操作，不只读 SQL；撤销后结果不再可见 |
| 费用 | 项目任务账本、执行任务与供应商日账 | 按上海自然日、项目、币种拆实扣/估算/混合；失败、提交后未知和 Worker 中断而未落账的任务均计入“待对账”，不计零、不等于供应商总账 | 核对当日调用次数和本地账本；火山实际账单未接通时明确标注未对账 |

## 真实案例判定

先使用非“九九”试点项目的已知充分人声样本验证完整链路，不创建“九九”业务项目。已有全局《那一刻，我也被净化了》可作为候选，但其历史审核不能自动继承为项目 A 审核。至少保留一个低人声或转写不足的反例，证明系统能拒绝不具研究价值的内容；再选择不同表达类型的第二条真实口播/对话样本，避免从一个成功视频推出普遍有效。

每个正例不仅需要 API 成功，还要由人判断：转写是否抓到核心信息、L3 是否指出具体可复用的开头/叙事/互动机制、哪些结论只是猜测、项目下一步行动是否能落为决策卡并在后续发布数据中复盘。未产生可执行判断时，记录为“技术链路通过、业务价值未验收”。

## 发布与故障门槛

1. 032 源码先进入可复现 Git SHA，Windmill 新脚本依赖固定到该 SHA 并生成锁；先备份、再迁移、执行 `verify`，然后隔离恢复对比 7 张项目私有表的存量。不能把数据库成功等同于 Raw App 发布。
2. 以最小 App Reader 权限实测 A/B/C；后台脚本只接受持久化 ID，配置/Key/媒体 URL 不作为调用参数。
3. 外呼前再次锁定审核；模拟撤销与提交/轮询并发、HTTP 后未知状态、对象丢失、Worker 中断；不能因恢复而重新 submit。同 Key 重放必须零新增外呼。
4. 记录测试日期、视频/项目 ID、审核指纹、Provider 任务号、提交与轮询次数、转写质量、L3 版本、页面截图/读取结果、项目账本和供应商日账状态。证据中不包含 API Key、私有 URL 或完整敏感正文。

当前本地 PostgreSQL + MockProvider 只支持实现层校验；真实付费端口和测试服页面验收仍待上述发布门槛完成。测试不设人为金额上限，但依旧保留防重复提交、有限轮询、审核和费用如实记录这几个正确性约束。
