## 业务边界

- 输入：项目已纳入的公开原帖、真实画面与声音核看、关键事件完整性、可核实事实、证据缺口、反证及与项目的可比边界。原帖必须是与 `source_video` 平台及作品标识相符的 HTTPS 直链；不会把私有 IP 设定发给外部服务。
- 输出：项目私有、追加式 `project_video_case_review` 版本，状态为 `partial`、`complete` 或 `insufficient`。没有看完整视频与必要声音、关键事件未完整入镜或无可比说明时，不能标为完整案例；证据不足可以不编造“已核实事实”。
- 接口：研究台视频库可读取项目内最新版本；Owner、Admin、Researcher 可对已纳入视频新增版本，其他项目成员只读。来源直链须匹配平台和已知作品路径中的精确作品 ID；仅匹配上游保存的 `source_url` 不足以验明原帖，未知路径不放行。
- 协作：纳入是“收录候选”，不等于案例核看完成；ASR/L3 可辅助分析声音和文本，不代替画面核看。项目 A/B 授权不复制该私有核看。

## 决策链

新行动卡的主要参考和并列案例/反例，都要求该项目该视频当前 `accepted`、公开源可用、最新版核看为 `complete`。后端、页面候选列表和 PostgreSQL 触发器三层执行。建卡时的核看版本 ID 固定到卡片及每条并列依据；后来追加 `insufficient`、撤回或公开源不可用，都不改写当时记录。旧卡保持可读，并标明未绑定版本或当前不完整；不能把它们按新门槛视为已验收。

执行中的卡片若任一绑定案例已有新核看版本、撤回或失效，或“采用”卡绑定的人设档案不再获准/权利已失效，页面、写入接口与数据库触发器均暂停新增发布与采用推进，允许归档；既有发布结果仍可登记每日汇总和复盘，不抹去历史。需要继续试验时以当前完整案例、有效档案重建行动卡与预登记口径。

行动卡不是业务成效证明。只有自有内容实际发布、按日非个人汇总、事先定义的主指标与观察窗、同类对照及干扰因素具备，才可评价方法是否支持原假设。公开视频热度不能代替渔岛/九九的实际结果。

## 本机验收与发布顺序
