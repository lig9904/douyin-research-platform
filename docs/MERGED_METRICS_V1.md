# 视频指标合并展示

用户主页面只看一份合并数据，历史及逐字段来源默认折叠。该策略仅用于展示与只读检索，不修改原始快照，不改变 L1 原始时间序列评分。

## 字段规则

- 播放量、账号粉丝：优先最近非缺失榜单记录，包含真实零值；没有该字段的榜单记录时，回退到最近非缺失记录。
- 点赞、评论、分享、收藏：取最近非缺失记录，包含零值；同时间按快照 ID 排序。不是取数值最大值，也不是永久优先某个详情接口。
- 全部来源缺失的字段仍为 NULL，显示为 `—`。
- 每字段保留来源分类和采集时间。合并记录的时间只是最近一个已选字段更新时间，不代表全部字段同时更新；旧榜单值可能滞后，展开依据可查看。
- 跨时间字段计算的互动效率标为“合并估算”，不能当作同一时点的增长证据。接口返回更高不等于已验证更准确。

## 消费范围与上线顺序

迁移 `018_merged_video_metric.sql` 创建只读视图。视频库列表/详情/过滤、首页、账号库视频、热点库、Windmill 研究查询及只读 MCP 统一使用该视图。账户自身快照、原始指标历史和采集/评分继续使用原始数据。

部署必须先备份、执行迁移并验证，再发布受影响页面与查询代码。不能仅推前端，否则后端因缺少视图失败。回滚应用时可保留新增视图，不删除快照或回滚用户数据。

基础 Schema 同步包含视图，新环境无需依赖补跑迁移才能查询。升级迁移仅为已存在且拥有原始指标读取权限的默认 `l3_local_reviewer` 补 SELECT；不创建角色、不授予写权限。自定义只读用户名必须由运维核对现有授权后对该确切角色补视图 SELECT，并以该角色运行查询验收，不能假定 bootstrap 会在旧卷再次执行。

验收覆盖：榜单与详情冲突、真实零、NULL、无榜单回退、最新值小于旧值、未知来源不泄露原端点、逐字段时间和来源、列表过滤与详情一致。当前隔离数据库测试通过不等于服务器实际生效；上线后须查看真实视频合并结果及默认折叠状态。
