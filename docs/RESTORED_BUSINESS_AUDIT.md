# 恢复库业务关联审计

`scripts/test-server-restored-business-audit.py` 只读检查已存在的
`test_server_research_restore`。通过环境变量
`TEST_SERVER_RESTORED_RESEARCH_DSN` 提供连接；不要把连接串写入日志或提交。
工具不创建、不恢复、不删除数据库，也不调用供应商接口。

检查媒体、转写、分析、执行任务和费用记录的关联，并统计同一视频下同时存在
已完成 ASR 与 L3 记录的数量。输出仅含聚合计数，不含正文、签名 URL 或凭据。
退出码 0 表示发现业务链记录且未发现所检查的关联错误；非零表示不满足或检查失败。

## 证据边界

- `business_chain_present` 不是恢复验收通过；`v1_release_accepted` 始终为 false。
- 同视频关联不证明某次 L3 实际使用了某份转写，还需核对输入指纹和审核证据。
- 不验证 MinIO 对象存在、内容校验和、权限、备份前后逐行一致或页面可用性。
- 不与运行中的数据库计数强行比较：备份后采集会使两者合法地不同。
- 恢复演练在清理之前通过 `test-server-restored-business-sql.py` 生成共享审计 SQL，使用现有容器内 psql 执行；不要求服务器额外安装 psycopg。固定恢复库校验与只读事务仍然强制执行，未通过时不得输出恢复成功标记。原有临时库清理边界不变。
