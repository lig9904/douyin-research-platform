# 抖音研究平台 V1 收尾任务书

更新日期：2026-09-21  
执行负责人：Codex 主流程；用户负责最终业务验收及必须由本人完成的授权。  
目标：让研究台在测试服务器上持续产出可用的真实研究结果，而不是仅有页面、模拟数据或单独接口测试。

## 一、交付定义

必须完成同一批真实业务数据的闭环：

发现视频 → 详情和指标入库 → L1 排序 → 按规则采集评论及生成 L2 特征 → 下载媒体、提取音频、存入私有 MinIO → 云端转写 → 合格候选进入 L3 分析 → 结果入库 → 研究台查看证据、转写、分析及每日费用。

不是所有视频都必须调用模型。每条视频必须有可解释的处理状态、跳过原因或失败原因；不得把真实缺失值伪装为零，也不得伪造转写、审核或分析结果。

V1 完成必须同时满足：
1. 测试服务器真实链路通过，不用本机模拟结果替代。
2. 用户能在研究台看到并使用结果，无需操作脚本。
3. 定时任务不依赖浏览器登录，重复执行不重复付费。
4. 每日费用可见，未接入或未知金额明确标注。
5. 代码、迁移、配置说明和验收记录可追溯到 GitHub 提交及部署版本。
6. 完成备份恢复与回滚验证，再发布正式 V1；测试通过不自动等于用户验收。

## 三、执行工作包

### T0：收敛分支和审查问题（P0）

- 输入：PR #67、#68、本地 ASR/L3 未提交修改、独立审查意见。
- 工作：保留既有修改；分离费用、存储、分析接入的提交；修复审核身份不得由请求方自授、媒体审核必须可追溯的问题。不得直接部署当前未审查的服务层。
- 输出：边界清楚的 PR、回归测试、部署顺序和回滚点。
- 接口/协作：主流程决定服务端身份与审核记录契约；子任务只做独立探索、机械验证或只读审查。
- 验收：调用方无法通过自填 actor/allowlist 取得权限；缺失或不匹配媒体审核记录时不触发外部调用；CI 通过且主流程实际复核。用户取消金额上限不等于取消身份验证。

### T1：每日实际费用上线（P0，可独立交付）

- 输入：TikHub Secret、研究数据库、供应商当日用量响应。
- 工作：部署迁移 015、费用同步脚本和页面；检查并复用已有同路径计划，启用每小时同步；手动运行一次。
- 输出：首页当日累计、每日列表、更新时间及失败/过期提示。
- 接口：GET /api/v1/tikhub/user/get_user_daily_usage；supplier_daily_spend；Windmill 同步任务。
- 验收：供应商响应、数据库和页面金额及账期一致；失败不写零；历史快照标明未终账；USD/CNY 分开；刷新费用不触发视频采集。
- 后续：为实际使用的火山服务接入日账来源；阿里仅在启用其业务调用时接入。暂不能取得实际账单时明确未同步，不用估算冒充实扣。
- 边界：用户只需知道每天花多少钱，不新增逐笔对账和按任务分摊工程。

### T2：真实媒体进入 MinIO（P0）

- 输入：真实已入库视频的合法下载信息、现有 S3 凭据、私有桶。
- 工作：实现下载、音频提取、文件指纹、对象入库、失败状态和临时文件清理；凭据保存到受控 Secret；上传走内网，外部读取使用 HTTPS 签名。
- 输出：与视频绑定的媒体元数据，研究台可播放/查看，转写任务可取得短时有效音频链接。
- 接口：S3 适配器、媒体记录、Windmill 媒体任务、研究台媒体展示。数据库保存对象 key，不长期保存临时签名 URL。
- 验收：服务器处理真实媒体成功；下载前后摘要一致；重复处理复用文件；失败不标记成功；匿名访问拒绝；签名过期能够重新生成；无密钥或签名写入日志。
- 边界：不将管理控制台对外发布；不设置公开桶；不新增应用服务器 Nginx；不删除已有用户媒体。

### T3：评论、L2 和候选晋级接通（P0）

- 输入：已采集视频、真实评论、已有特征提取器和候选规则。
- 工作：补齐服务端任务入口和研究台状态；将 L2 特征、候选选择及来源证据持久化。
- 输出：每个视频的分析资格、优先级及原因，不合格项明确跳过。
- 接口：评论采集任务、CommentFeatureExtractor、L3PromotionGate、研究台审核入口。
- 验收：同一批数据可从页面追溯到评论与特征；重复运行不重复创建相同结果；无需浏览器登录即可运行定时任务。
- 协作：数据探索可与 T2 并行，涉及相同数据库迁移和状态机的修改由主流程串行集成。

### T4：ASR → L3 → 页面闭环（P0，依赖 T0/T2/T3）

- 输入：已审核的真实音频、持久化候选及证据、受控 Worker 身份、火山配置。
- 工作：部署真实 ASR 与 L3 任务入口；持久化提交、轮询、转写和分析状态；研究台展示内容及证据，支持安全恢复失败任务。
- 输出：与原视频对应的真实转写、结构化分析、可追溯证据和任务状态。
- 接口：火山 ASR/Ark Provider、执行协调器、研究数据库、研究台详情页。
- 验收：中断后恢复轮询不重复提交；同一输入重复触发不重复付费；审核与输入变更能正确失效；未知费用不写零；成功结果持久化并在页面可见。
- 边界：不测试 qwen-flash；不做无业务价值的大批模型对比；保留证据和身份边界，不重建用户已取消的默认金额上限。

### T5：自动运行和业务验收（P0，依赖 T1–T4）

- 输入：完整已部署链路、业务采集规则、固定的小规模测试批次。
- 工作：先运行至少 3 条真实视频，至少 1 条合格且有语音的视频完整经过媒体、ASR、L3 和页面；其他记录保留真实状态，不强迫无效视频进入模型。
- 输出：可查看的真实研究案例及持续任务运行记录。
- 验收：
  - 同一案例的视频 ID、媒体、评论、转写、分析和页面结果一致。
  - 至少观察两个连续调度周期，并完成一次受控失败恢复验证。
  - 服务端任务不依赖人保持网页登录。
  - 重跑不重复采集同一证据、不重复付费提交。
  - 页面没有把“未采集/未知”当作真实 0，错误有明确提示。
  - 用户可以完成“找视频 → 看依据 → 看分析 → 查看每日费用”的实际使用流程。
- 顺序：真实付费链路串行进行，避免并行测试重复消耗；无需付费的独立验证可并行。

### T6：运维与 V1 发布（P1，闭环通过后）

- 输入：验收通过的提交、迁移、运行配置和数据备份。
- 工作：检查任务失败可见性、存储与临时文件增长、数据库与媒体引用备份；在隔离目标验证恢复；形成可执行回滚记录；更新 GitHub 文档、发布说明与版本。
- 输出：明确部署版本、验收报告、恢复/回滚记录和 V1 发布。
- 验收：备份可实际恢复且媒体引用有效；回滚路径不覆盖未知用户数据；发布说明明确已完成与已延期内容。没有相应证据不得宣称通过。
- 边界：不擅自发送真实通知；需要外部通知渠道时先准备方案，再由用户确定接收方。

## 四、并行与提交规则

1. 主流程负责架构、集成、部署、费用调用和最终验收。
2. 可以并行：只读审查、独立模块测试、互不改同一文件的文档与实现工作。
3. 不并行：同一文件、同一数据库迁移序列、同一业务状态机、同一服务器发布、真实付费链路。
4. 子任务“完成”必须经主流程实际复核，不直接作为验收证据。
5. 每个工作包维护四个独立状态：已实现 / 已测试 / 已部署 / 实际生效。
6. 每次部署记录完整 SHA、迁移、验证结果和回滚点；不把浮动分支名当作版本证据。
7. 不以覆盖其他人的修改、跳过测试、伪造数据或放宽权限来追求进度。

## 五、范围与用户参与

- 现有服务器、反代、域名、500G 盘和 MinIO 已具备，不要求用户重复搭建。
- 优先让抖音真实链路可用，不扩展多平台、控制台重做、无必要的模型评测或复杂费用分摊。
- 已授权的小规模、有效付费测试继续按业务需要执行，清楚记录费用；遇到必须操作时确认的工具规则照常遵守。
- 仅遇到缺失配置、实质扩大权限/数据公开范围、真实通知接收方或影响业务结果的选择时请求用户决策。
- 不承诺没有现场证据支持的完成百分比或截止时间；按上述工作包和验收结果报告进度。

## 六、下一次执行顺序

T0 审查收敛 → T1 费用上线，同时完成 T2/T3 的独立准备 → T2/T3 集成 → T4 真实分析闭环 → T5 连续自动运行验收 → T6 发布。

首个交付点：研究台可查看每日实际费用。  
核心交付点：研究台可查看一条真实视频的完整媒体、转写和分析。  
最终交付点：无需用户盯着页面，也能持续出结果，并具备可验证的费用与恢复能力。
