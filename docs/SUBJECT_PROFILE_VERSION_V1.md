# 通用主体档案版本：第一阶段代码边界

状态：本地候选代码，未迁移测试服、未创建“九九”项目，也未接入 L3 或创作行动卡。

## 业务输入与输出

- 输入：项目中已有的研究主体；由项目 Owner/Admin 提供五类以内的短摘要（目标客群、可拍场景、叙事边界、禁用表达、当前事实），并填写受控来源引用、来源资料 SHA-256 和权利状态。系统不接收完整剧本、媒体或凭据。
- 输出：项目内版本号、生命周期、内容指纹和可读摘要。普通项目成员只能读取已核准版本的最小字段；项目管理者可查看草稿、历史和来源引用。
- 适用类型：IP 叙事、景区体验、活动转化和其他，不把“九九”写死在模型或页面中。

“已核准”表示负责人确认档案摘要及所填来源，**不等于素材使用许可**。权利状态为 `unknown`、`pending`、`restricted` 或 `prohibited` 时，后续创作、媒体利用及 L3 必须另行拒绝；即便为 `cleared`，仍需核验对应作品、素材和人工审核。来源 SHA-256 是操作者提交的指纹，当前系统不读取原件自动核真，不能把有指纹误当作已验证权利。

## 接口、权限与版本

- `get_subject_profiles(project_id, subject_id, include_history)`：绑定 Windmill 终端用户身份及项目成员 ACL。非管理者即使传 `include_history=true`，也只返回当前已核准短摘要，不返回来源引用、来源摘要或审批人。
- `mutate_subject_profile(project_id, subject_id, action, idempotency_key, ...)`：仅 Owner/Admin 可创建草稿、核准、标记替换或撤销；所有操作保留幂等审计。版本号由后端在锁定主体后自动分配，前端不能指定。
- 版本流程：新草稿可核准或撤销；已核准版本可标记替换或撤销。一个主体同时至多一个核准版本；换版需先保存新草稿，再标旧版为已替换，最后人工核准新版。三步不具备原子性，中间无可引用版本，不能把旧版自动复用。撤销后的草稿和已核准历史均保留审计信息，不可原地改写。
- 表 `research_subject_profile_version` 限定项目与主体组合外键、非空摘要、允许字段和摘要体积，数据库生成 SHA-256；核准后正文不可原地改写或删除。档案行保留审计历史，外键采用 `RESTRICT`，不能靠物理删除主体或项目级联抹除。

## 协作与验收边界

- 内容负责人负责确认事实、禁用表达与权利状态；研究员只读已核准摘要。没有官方账号也可以准备档案代码，但目前不创建真实业务项目。
- 本阶段验收为：隔离 PostgreSQL 迁移与 ACL/生命周期动态测试、Raw App 构建、跨项目与撤权拒读、草稿和来源不泄露、版本指纹稳定。
- 下一阶段才可建立“档案版本 → 行动卡/发布稿/L3 审核”的精确引用与失效门禁；未完成前不能声明九九内容闭环或素材已可用。
- 当前页面在同一打开会话内保留不确定网络请求的幂等键并刷新历史对账；浏览器整页刷新后仍可能丢失待确认键，实际测试服部署前需补跨刷新恢复或明确的人工对账流程。
