# 评论 → L2 → 候选批次执行契约

## 输入和输出

服务 `CommentPipeline` 接受已成功的 `l0l1_discovery` 批次 UUID；只处理该批次 `L1/scored` 的视频，不修改原始批次。最多 20 条，超过时明确拒绝，不静默截断。

构造时注入服务端数据库、评论采集器和受控 Worker 身份；调用参数包含评论样本配置与晋级规则。返回独立批次 ID、逐视频结果、候选来源批次 ID 和晋级结果。当前为服务层实现，尚未部署 Windmill 批次入口或真实评论调度。

## 重放与失败恢复

- 采集幂等键只绑定来源批次、规则版本及评论采集参数。修改 top_n、分数门槛、配额日期或配额键不会重新请求评论。
- 调用采集器前持久化 collecting。采集异常或中断导致结果不确定时返回 reconciliation_required，不自动重复可能已计费的请求；需核验供应商/持久化证据后另行恢复。
- 已采集但特征提取失败时，只重试特征提取。
- 候选来源是成功视频集合及其特征指纹绑定的不可变批次。部分失败恢复后新建完整集合，旧集合保留不变；已有晋级器负责每日去重和配额。
- 同一来源和规则版本由数据库会话锁串行化。当前是阻塞锁，调度层仍需配置任务超时；跨不同来源发现的同一视频是否需要重新采集，仍遵循上游缓存/业务采样规则，不声称跨所有批次免费复用。

## 已有验证与待验收

本地隔离 PostgreSQL 测试验证了 A 成功/B 提取失败后 B 恢复、旧候选集合不可变、A 不重复消耗配额、修改晋级参数不重复采集、原始 L0/L1 不变，以及结果不确定时不重发请求、不使用视频旧 L2 晋级。

上述集成测试使用真实数据库及真实晋级器，但采集器和特征提取器使用合成替身，没有调用 TikHub。真实评论归一化、特征提取与页面追溯还须在测试服务器同批样本中验收，不能由这些测试替代。

上线前需完成固定服务端配置的 Windmill 入口、真实样本链路、并发/超时验证与运行状态页面；不新增默认金额限制、不绕过隐私审核、不自动发起 ASR/L3 调用。
