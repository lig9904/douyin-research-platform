## 输入、输出与权限

- 输入：Windmill 服务端提供的 `WM_END_USER_EMAIL`、当前项目、已注册用户邮箱及所选角色。浏览器不能自报操作者身份。一个项目可有多名成员，一个成员可分别加入多个项目；加入 B 不会继承 A 的权限。
- 项目成员角色：负责人 `owner`、管理员 `admin`、研究员 `researcher`、分析员 `analyst`、只读成员 `viewer`。负责人可管理所有角色，管理员仅管理研究员、分析员和只读成员；最后一名负责人不可撤销或降级。成员的新增、改角色和撤权均追加有效期名册记录，保留历史，项目接口按最新生效记录判权。
- 协作页面输出：管理者可看到本项目成员、同组织可作为目标的项目、发出/收到的共享授权；普通成员只看到自己的角色与已获准的共享证据。权限不明、项目或组织停用时拒绝，而非回退到全局历史库。
- 审计：成员变动和共享状态变化写入 `project_access_event`；页面不返回审计库的原始记录、凭据或后台授权信息。

## 项目间授权

默认无共享。当前唯一可授予范围为 `public_video_evidence`：来源项目负责人/管理员向同组织的目标项目发出邀请，目标项目负责人/管理员接受后生效；最长 365 天，到期自动停止读取，双方均可撤销。目标项目普通成员只能查看来源项目**明确标记为 `accepted`** 且当前标记为可用的视频的公开标题、平台、公开账号名和合并公开指标，以及来源项目名称。自动发现的 `candidate`、`shortlisted`、已拒绝或已归档的视频均不共享。数据库函数在每次读取时核验目标成员、两个项目与组织状态、授权状态/有效期、来源项目纳入状态和视频可用状态。此加固由迁移 026 提供；未部署 026 的测试服仍按旧规则运行，不得把本地代码当作线上已生效。

本次**不共享**评论审核原文、转写、媒体对象、L3 结论、成本、原始 Provider 响应、项目私有设定或平台账号授权。共享内容在“项目协作”中单独展示，不将目标成员冒充为来源项目成员，也不修改原视频归属。未来扩展其它资料类型时应逐项增加归属与策略，不把 `public_video_evidence` 擅自扩展为“共享全部”。

## 接口与协作

`get_project_collaboration(db, project_id)` 是只读入口；`mutate_project_collaboration(db, project_id, action, ...)` 管理成员与共享状态。两者只接 Windmill 受控的研究库资源，页面不接收数据库密钥。Windmill 用户创建和登录仍由 Windmill 负责；本功能只管理业务项目成员，不创建账号或修改密码。Raw App 只能精确发布 `f/content_research/research_dashboard`，不能全工作区同步。

视频库新增 `manage_project_video_evidence(db, project_id, action, video_reference, idempotency_key)`：项目负责人/管理员输入精确抖音视频 ID 或直链，先预览**现有公开库**中的标题、公开账号和合并指标，再确认将该视频状态设为 `accepted`。该操作不调用 TikHub、不自动批量纳入历史视频、不复制全局 ASR/L3 结果；成员身份仍来自 Windmill 服务端，写入通过 `research_user_action` 记录操作者、动作、幂等键与结果。找不到视频时应走项目研究任务采集，不把任意 URL 当作已入库证据。代码、CI、测试服 v42 发布及真实页面预览/写入均已验证。

### 后续只读数据库复核（2026-09-24）

- 测试服 `project_access_event` 中查到本次 `share_offer`、`share_accept`、`share_revoke` 各 1 条；三条顺序、A/B 操作者、相反方向的来源/目标项目和同一个 grant ID 均与浏览器操作对应。未发现该链路多写授权事件。
