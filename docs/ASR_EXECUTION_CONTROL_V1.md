# ASR 付费执行控制层 V1

日期：2026-09-19

## 结论

本层实现真实 ASR 调用所需的供应商无关控制面，但不假定第三方中转的 URL、模型名、鉴权和响应结构。

当前已经完成：

- 默认零调用预览
- 精确人工确认
- L2 准入检查
- 固定日预算键
- 单并发锁
- 稳定任务键
- 一次提交
- 持久化供应商任务状态
- 后续只轮询、不重复提交
- 单次运行轮询硬上限
- 每次外部调用前原子占用请求预算
- ASR 提交前预留已知的 API + ASR 估算成本
- 完成后写入 ASR 证据与实际成本账本
- 失败时记录未知实际成本，不自动退款
- 返回与异常脱敏

具体中转适配器必须在核实真实契约后另行实现。

## 人工执行条件

正式运行必须同时满足：

1. `execute=true`
2. `confirmation=RUN_ASR_PAID`
3. 视频已经达到 `research_level >= 2`
4. API 与 ASR 估算成本都已知
5. 当天已经配置 `provider / windmill_manual_asr` 的 `daily_budget`
6. 请求币种与预算币种一致
7. Provider 明确配置 `max_retries=0`
8. PostgreSQL advisory lock 获取成功

任一条件不满足，都不会调用 Provider。

## 预览

`execute=false` 时只返回：

- 最大外部调用次数
- 估算总成本；未知则为 NULL
- 币种
- 是否具备已知成本
- SDK 重试数 0
- LLM 调用数 0

预览不检查数据库、不读取 Secret、不构造 Provider、不保存任务，也不返回视频、任务或媒体标识。

## 提交与轮询

单次运行最多：

- 提交 1 次
- 轮询 0–3 次
- 总外部调用 1–4 次
- 自动重试 0 次

提交前先原子占用一次请求额度和已知的 API + ASR 估算成本。轮询前逐次占用请求额度，轮询成本按 0 预留；如供应商对轮询收费，具体适配器接入前必须修改估算规则。

供应商提交返回的任务引用会持久化。后续相同 `task_key`：

- 已完成或失败：直接返回已有状态，不读取 Secret、不调用 Provider
- 已提交或运行中：只轮询，不重新提交
- 停留在 `submitting` 且没有可靠任务引用：返回 `reconciliation_required`，禁止猜测性重提

提交成功不等于 ASR 完成。

## 预算与失败

本层采用保守记账：

- 每次外部尝试前先占预算
- 提交或轮询抛出异常后不自动退款
- 不依据异常文本猜测“供应商肯定没有计费”
- 提交失败会生成 `research_task_cost(status=failed)`
- 无法确认的 API/ASR 实际成本保持 NULL
- 本层不使用 LLM，明确记录 `llm_cost=0`
- 任一实际成本未知时，`total_cost=NULL`

预算是否人工调整由管理员另行判断，执行代码不会扩大预算。

## 数据与日志边界

数据库保存：

- 稳定 `task_key`
- 供应商与模型版本
- 输入媒体指纹
- 媒体引用的 SHA-256，不保存媒体引用明文
- 内部供应商任务引用
- 提交/轮询次数
- 预算日期与估算成本
- 脱敏错误码
- 完成后的证据及成本账本引用

外部返回只包含聚合状态、提交/轮询次数、当次外部调用数、是否已有成本账本和脱敏错误码。

不返回：

- 视频或媒体引用
- Provider task ID
- Secret、Token、请求 ID
- 原始上游错误
- 原始响应
- 余额或账户总额
- 内部数据库 ID

## 尚未完成

V1 控制层使用 `ASRProvider` 协议注入具体适配器。以下内容尚未实现，也不得凭经验假定：

- 第三方中转 `base_url`
- 提交和查询路径
- 鉴权方式
- 模型名称
- 媒体传递方式
- 异步任务字段
- 结果、分段和成本字段映射
- 轮询是否收费

只有取得并核验中转接口文档或最小脱敏样例后，才能实现具体 Provider 和 Windmill 手动 Flow。本仓库仍不附带 schedule。
