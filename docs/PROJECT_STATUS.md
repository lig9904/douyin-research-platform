## 4. 协作与合并规则

- GitHub 是代码、文档与状态的唯一事实来源。
- 一个可验收任务对应一个独立分支和一个 PR。
- 不允许两个执行端同时修改同一分支。
- 实现端负责代码、测试、分支和 PR；总控端负责范围、官方契约、成本、安全边界和 PR 审查。
- PR 必须通过编译、单元测试和 PostgreSQL 集成测试。
- 未通过 CI、未审查 Diff 或未确认生产闸门，不得合并。
- 不以聊天中的口头汇报替代 GitHub 证据。

## 5. 密钥与付费调用边界

- 密钥不得进入聊天、Git、Issue/PR、数据库、测试夹具或日志。
- 正式凭据只允许放在受控部署环境的 Secrets 中。
- `.env.example` 只列变量名，不包含真实值。
- 未获得单独明确授权，不得发起真实或付费 ASR/LLM 调用。
- 预览默认零调用；SDK 自动重试为 0。
- 失败或中断后费用未知时保留 `NULL`，不得伪造为 0。
- `production_ready=true` 只能在官方契约、账户权限、计费、模型和真实验证均完成后由操作人明确启用。
