写库准备另补了多产品同日快照的单事务批量写入：任一产品范围因旧时间戳或终账保护未被接受时，整批回滚，不能只更新半天产品账。单行及批量写入都不允许后来抓取的 `preliminary` 覆盖已经登记的 `final`；`final` 仍只能由供应商明确的终账事实指定，不根据账单日期自动推断。批量函数只保证**传入产品集**原子，不会自动删除或核对数据库里未传入的历史产品范围；正式同步前要固定/版本化完整产品集，并制定产品集变更时的旧行处理与页面展示规则。该能力尚未连接到线上火山同步脚本，不能视为已对账。

## 2026-09-27：一次真实只读 OpenAPI 回包

通过已登录账户的官方 API Explorer，仅对 `2026-09-26` 执行一次 `ListBillDetail`。请求使用 `BillPeriod=2026-09`、`ExpenseDate=2026-09-26`、`GroupTerm=2`（产品）、`GroupPeriod=1`（按天）、`IgnoreZero=0`、`NeedRecordNum=1`、`Limit=300`，未设置产品过滤。HTTP 200，响应 `Total=2`、`Warning=""`，列表仅有 `TOS`（对象存储）及 `Doubao_Seed_ASR_AUC_2.0`（豆包录音文件识别模型2.0）；两行均为 CNY，`PayableAmount`、`PaidAmount`、`UnpaidAmount` 返回 `0.00`。请求 ID、付款方 ID 和原始账单内容未写入公开仓库。

这次真实回包确认了 ASR 的产品代码、日产品分组和金额字段，却**没有方舟模型产品行**。缺行不能解释为方舟费用为零，也不能断言此日最终无使用量；近期账单仍可能延迟。当前手动同步脚本若把方舟列为预期产品，会按设计拒绝写入该日期，而不是默默补零。该回包也只证明控制台登录态可读，**不证明**专用账单 AK/SK、Windmill Secret 或服务器定时同步已可用；041 LAS Worker 发布与账单同步是两条独立工作流。

同日再以 `GroupTerm=3`（账号）、`GroupPeriod=1`（按天）、相同付款方和日期、不设 `Product`，做了一次只读查询：HTTP 200、`Warning=""`、`Total=1`、`Limit=300`、`Offset=0`，`ResponseMetadata.Action=ListBillDetail`、`Service=billing`；唯一行的 `BillPeriod="2026-09"`、`ExpenseDate="2026-09-26"`、`Product/ProductZh=""`、`Currency="CNY"`、`PayableAmount/PaidAmount/UnpaidAmount="0.00"`，`PayerID` 与输入付款方一致。该字段级回读验证了当前账户的严格解析条件；不证明未来其他账期字段恒定，也不证明签名 AK/SK 请求。它证明当前账户可由供应商直接给出日总额，而不必把缺失产品行当作零去凑总数；但仍属未终账的近期快照，也不是“九九”项目独占费用。原始账单、付款方 ID 和请求 ID 未公开。

## 2026-09-28：零应付与非零折后价的真实区别

官方 API Explorer 对 2026-09-27 的付款账户按天汇总返回 HTTP 200、`Total=1`、`Warning=""`：`OriginalBillAmount` 与 `DiscountBillAmount` 均为 `0.000015` CNY，`PayableAmount`、`PaidAmount`、`UnpaidAmount` 则均为 `0.00` CNY。请求范围为单个付款账户、单日、`GroupTerm=3`、`GroupPeriod=1`；付款方身份和原始响应没有写入公开仓库。该近期账单仍未终账，也不是研究项目独占费用。

因此日账的“应付/已付/未付”必须采用同名账单字段，不能用原价或折后价替代；同时，`0.00` 应付不能被解释为没有用量或没有外部调用。研究台对此补充了说明，解析器增加小额非零折后价但零应付的回归测试。下述真实发布记录更新了本段写成时的待办状态。
