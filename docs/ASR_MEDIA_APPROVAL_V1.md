状态：服务层、资产输入 Worker 与隔离测试已实现；尚未部署真实转写任务及页面审核入口。

页面接入实现：视频详情增加音频列表、短时签名试听及保存审核。后端 `asr_media_review` 仅接受视频/资产/版本/动作/预览指纹；固定读取数据库与审核配置。列表不返回对象 key；试听先验证审核员与视频资产绑定，再核验私有对象，签名有效期 300 秒。页面成功提示以批准接口真实返回为准；音频未加载、播放报错、已撤销或已批准时不可再次保存。切换视频通过组件 key 重建状态，刷新列表/切换音频清除旧确认。

链接不持久化到研究数据库；但播放链接会作为 Windmill 作业结果返回，属于短期 bearer URL，应保持工作区作业结果访问受控，避免导出带链接的调试日志。未修改桶匿名权限。当前已做后端测试与前端构建，浏览器窗口不可用，未完成真实视觉、试听和保存交互验收，不能直接作为已上线能力。

迁移 017 增加 `asr_media_review`，记录音频资产、审核版本、资产指纹、HTTPS 投递源、审核人和有效状态。审核使用固定服务端审核员名单与 Windmill 已认证用户身份，禁止请求自行提供 actor 或 allowlist。资产指纹绑定视频归属、对象 key、内容摘要、大小及类型；临时签名查询不进入指纹。审核时验证预览指纹，已有撤销版本不会因重试批准而重新激活。

`LiveASRRequest` 必须指定已审核资产 ID、审核版本及内容摘要。执行前重新读取持久化审核，校验投递源和完整对象路径；缺失、撤销或错配会在 Provider 构造前拒绝。自动执行身份只读取 `f/content_research/automation_worker_identity`，不依赖浏览器登录或调用方姓名。人工审核身份与自动运行身份是不同责任。

任务键绑定视频、内容与模型版本，不绑定临时签名；链接更新后恢复同一提交并继续轮询。跨日恢复沿用原任务账期，显式更换账期仍视为输入冲突。费用未知保留 null/unknown，在已明确配置为不限金额时不因缺少报价阻止业务；已有请求护栏及明确金额限制仍生效。

本地测试使用隔离 PostgreSQL 和假 Provider，没有实际付费转写：覆盖缺失/撤销/错配审核、未授权身份、预览变化、签名轮换、原任务恢复、未知费用及零 Provider 构造拒绝。上线仍须完成审核预览与批准页面、固定 Secret 的 Worker 入口、服务器迁移、真实音频转写及页面展示验收。不得通过手工插入批准行替代真实业务审核。

## 固定资产 Worker

`f/content_research/analysis/run_reviewed_asr` 仅接收 `video_id`、`asset_id`、`review_version`。数据库固定读取 `f/content_research/research_db`，存储固定读取 `f/content_research/media_storage_config`；不接受调用方 URL、身份、数据库或密钥。

部署时需创建受控 Secret `f/content_research/asr_worker_config`，JSON 字段必须恰为：

```json
{
  "api_key": "<现有火山 ASR 凭据，不提交真实值>",
  "max_polls": 1,
  "max_daily_requests": null,
  "max_daily_cost_cny": null
}
```

`max_polls` 为 0–3；两个 null 表示明确不设对应上限，不是零费用。此处是配置契约，不代表服务器 Secret 已创建或自动计划已启用。自动身份仍由原有固定 `automation_worker_identity` 配置提供。

入口先校验审核与资产绑定，再 HEAD 校验对象摘要、大小和类型，并签发一小时投递链接。恢复沿用稳定任务键和原账期，不重置已有日账；已有任务但原账本缺失时停止，要求核对而非补零。只有新任务可按固定策略初始化当天账本，已有当天配置不覆盖。

`submitted` / `running` 表示仍需后续调度轮询，不能视为转写完成；失败或需核对状态使 Windmill 任务失败。轮询恢复继续调用同一入口和同一资产，不创建新的付费提交。上线须配置实际调度并验证两个周期，不能只部署脚本。对外错误固定脱敏，不返回签名 URL 或凭据。

## 待完成任务自动轮询

`analysis/poll_pending_asr` 无公开输入，固定读取已提交一次、具有供应商任务引用、状态 submitted/running 的 live ASR 任务；不会选择 submitting、终态或人工任务。每轮最多串行处理 5 条，按更新时间从旧到新；这是吞吐批次，不是金额上限。单条失败后继续本批其他任务，最终以脱敏汇总错误标记调度失败。

调度模板每 5 分钟执行，默认 disabled。须先发布更新后的 `run_reviewed_asr`，配置 `max_polls` 为 1–3，确认至少两个普通 Worker 可用，再部署并启用轮询计划。父任务同步等待子任务，因此不能仅给这一队列一个 Worker。不得把模板文件存在当作计划已启用。

轮询传入服务端持久化的 `resume_job_id`；Worker 会核对该 ID 的任务键和可恢复状态。模型/内容身份变化、旧任务不存在或原账本缺失时停止，不转为新的付费提交。缺失审核或损坏元数据保留待人工检查，不以删除旧任务或重置状态来恢复。旧日配额若已耗尽，轮询也会明确失败，不挪到新账期绕过。
