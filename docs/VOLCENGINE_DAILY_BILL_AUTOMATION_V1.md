# 火山账户日账自动对账 V1

本方案只处理火山费用中心 `ListBillDetail` 返回的付款账户、人民币、按日总账。它不是“九九”项目分摊账，不把任务报价、调用次数或模型 token 估算成实扣。供应商未出账、响应不完整或任务失败时，不写入零元账单。

## 输入、输出与协作边界

| 模块 | 输入 | 输出与使用方 |
| --- | --- | --- |
| Windmill 定时脚本 | 研究库资源、已核验 `payer_id` 配置、加密账单只读 AK/SK、覆盖起始日 | 逐日拉取官方账单；在同一数据库事务写入有效快照并解决对应缺口 |
| `volc_billing_sync_gap` | 付款账户和账期日期 | `pending/resolved`、尝试次数和下次可重试时间；仅是对账进度，不含金额和原始响应 |
| 管理员“运行与成本” | `supplier_daily_spend` 及缺口表 | 分开显示已取得的供应商金额与待核日期；缺失表/空队列/零应付都不推断为零使用量 |

定时模式每天北京时间 18:00 最多检查十个账户日：最近两天、最多七个较早待核日、一个最久未更新的旧初步快照。首次运行从配置的起始日建立缺口；已有有效账户快照初始化为已解决。失败的日期留在队列，跨滚动窗口继续重试；每次失败至少间隔 20 小时。官方账单无明确终账标记时，保存为 `preliminary`，不能自行宣称最终结算。已有真实 `final` 快照会在请求凭证和供应商 HTTP 前跳过。

待核原因只保存安全枚举：`bill_unavailable`（未出账）、`snapshot_rejected`（校验失败）、`scope_conflict`（旧产品范围冲突，需人工处理）和 `execution_failed`（其他任务故障）。手工补账成功也会在同一事务解决已登记的缺口，避免页面继续误报待核。

请求串行、间隔至少 250 毫秒；脚本单实例并发限制为 1，数据库按付款账户/日期使用事务级 advisory lock。有效快照和缺口解决在同一事务提交。供应商原始行、密钥与错误正文不写入应用账本、研究台或任务结果。

## 发布与验收

1. 确认脚本固定的核心库 Git 提交已推送、`.script.lock` 与 `wmill-lock.yaml` 同步，CI 的 Python、PostgreSQL、Windmill 校验通过。
2. 测试服先备份，执行加法迁移 `045_volc_billing_sync_gap.sql`，核验对象/权限并对迁移后的备份执行隔离恢复。旧运行库和媒体对象不覆盖。
3. 仅发布 `sync_volcengine_daily_bill` 脚本、单个研究台 Raw App 和该脚本的日计划。`windmill/wmill.yaml` 不包含 schedules，不能靠普通工作区同步推断计划已经发布。
4. 先保持计划禁用，手动执行一次 `billing_date=scheduled`。核对 Windmill 结果、缺口队列、`supplier_daily_spend` 账期/金额/`preliminary`、管理员页面四处一致；再开启日计划并核对下一次计划任务实际生成。
5. 到点后检查一次真实自动运行和页面回读；用受控失败证明待核日保留且未写零账单，恢复后同一日期成功对账。重新同步已终账日期必须零供应商 HTTP。

完成第 1–4 步只能说明部署与手动链路；没有第 5 步的真实到点记录，不宣称“自动日账已验收”。本文件是实施契约，不是当前测试服完成证明。历史单日真实账单证据见 [2026-09-28 手动对账记录](releases/VOLCENGINE_DAILY_BILL_REAL_20260928.md)。
