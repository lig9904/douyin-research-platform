# 螭吻九九内容研究闭环：现状与验收

日期：2026-09-23。九九是[通用内容研究闭环](CONTENT_RESEARCH_CLOSED_LOOP_V1.md)的首个 IP/演艺验收样本，不建设“九九专用平台”。对象是渔岛《螭吻九九·神兽觉醒》相关内容的持续研究、创作和复盘；不等同于景区所有产品的经营研究。2025 年公开报道确认九九与《神兽觉醒》曾亮相，但它只是历史背景，不授权复用报道中的画面或台词；具体角色设定、当前演出排期、素材权利和经营数据必须以渔岛提供的现期资料为准。[公开背景](https://www.visitbeijing.com.cn/article/4NHEOLI6pUF?device=amp)

2026-09-24 补充：用户明确首个业务试点是“九九 IP 号”长期运营，目标人群 18–35 岁，官方账号尚未建立。执行节奏与前置资料见[九九 IP 号试点](JIUJIU_IP_ACCOUNT_PILOT.md)。以下旧阶段描述保留历史设计语境；不能把页面/表结构的后续上线误读成已经有账号或已完成自有数据复盘。

## 当前能做到哪里

研究台可建立抖音关键词/账号任务；通用全局任务可按深度收集外部视频、指标和评论样本，对需要云端转写或 L3 的单视频仍须分别完成人工内容/隐私审核。测试服已具备项目主体相关性与行动复盘入口，但项目任务目前只采公开元数据；项目级 L1 评分仅在本地代码中，尚未部署。激活未来“九九”研究任务**不会**自动转写或分析。它能辅助“找依据、看案例、提出假设”，**不能宣称已形成九九内容闭环**。

具体缺口：尚未建立“九九”业务项目及权威的角色/故事线/场景/客群设定版本；项目 L3 尚未建立目标 IP 约束与审核链，不能借用旧全局 L3 结果；ASR 的九九热词表目前是策略文档，不等于已配置生效；缺少脚本版本与真实自有发布、效果回流和经验更新。通用行动卡的数据结构不等于九九选题已有采用记录。自有账号官方 API 自动回流仍是 [V2 规划](SELF_ACCOUNT_FEEDBACK_V2.md)，不得冒称已接入。

## 九九配置与责任

下表是通用模型在九九项目上的配置与验收目标；部分通用表和页面已在测试服，具体九九资料和记录尚不存在，不能据表格推断已完成业务验收。

| 环节 | 输入与责任方 | 输出与接口 | 验收 |
|---|---|---|---|
| 1. 九九知识底座 | 渔岛内容负责人确认角色、关系、世界观、剧情线、演出/互动实情、目标客群、禁用设定与素材权利；研究台只保存版本、来源和受控摘要，不把完整保密剧本写入公开仓库 | 通用 `research_subject`（IP/演艺/角色层级）和 IP 类型的 profile 版本；L3 审核材料引用确切版本 | 能区分“官方设定”“公开报道”“研究假设”，不能编造角色与剧情 |
| 2. 相关内容研究 | 研究员定义“螭吻九九/神兽觉醒/渔岛演艺”及可比文旅演艺、角色 IP、亲子互动等主题；有排除词和人工纠错 | 任务关联项目与场景；候选标相关/待核对/无关；源视频、评论、转写、视觉证据按需进入分析 | 同名游戏或无关“九九”不进项目研判；每条结论可回原始依据 |
| 3. 选题与创作 | 内容负责人选“采用/观察/否决”，指定角色、故事弧、核心看点、适用客群、渠道、发布窗口、素材与授权 | 选题卡、脚本/分镜版本、审核状态；明确“借鉴机制”和“不得照搬画面/台词” | 至少两种可比较内容角度，有负责人、主指标、观察窗与发布前事实/权利审核 |
| 4. 发布与效果 | 发布人员登记自有作品 ID、账号、发布时间、内容版本、投流/合作信息；初期可人工导入汇总数据 | 自有作品与选题卡关联；按可获得口径记录曝光、观看停留/完成、互动、关注、主页/活动入口点击及活动/售票汇总 | 同一作品能回链到设定、脚本和选题；缺少官方授权的数据如实留空，不用公开视频指标冒充自有后台 |
| 5. 复盘与经验 | 内容与运营共同核对受众反馈、演出排期、天气、节假日、投流、库存及线下执行 | 对假设写“支持/不支持/证据不足”，区分内容认知目标与到场/购票目标；形成待验证或已复现的经验 | 不把单条高播放归因于脚本，不把景区整体收入归因于九九；反例或重复样本不足时不升格为规则 |

抖音官方自有视频数据需要账号授权和相应权限；景区商品、订单或核销数据还需要对应商家权限和授权。第一版可用**无个人信息的人工汇总导入**完成一次业务试点，再评估自动接入。[官方视频数据](https://open.douyin.com/platform/resource/docs/ability/open-data/video-data-solution)、[生活服务开放平台](https://partner.open-douyin.com/docs/resource/zh-CN/local-life/connect/life-open-platform)

## 最小试点

由渔岛确认一个当前可拍、可发布的九九故事段落或互动场景，确认设定版本和授权素材；从相关且可比的案例提出两种内容角度，分别做选题卡。由渔岛决定是否制作和发布；若发布，登记作品与脚本版本，在预先写明的观察窗内记录自有账号和可获得的线下汇总结果，复盘哪一种叙事更能让目标客群理解、记住并采取行动。没有发布或没有可信效果数据时，研究只到“待验证假设”，不能写成已验证经验；单次结果也不直接升级为通用创作规则。

正式业务验收至少需要一条完整的“设定版本 → 有依据的选题 → 人工审核的作品 → 实际发布 → 自有指标 → 复盘 → 更新或保留规则”记录；安全/权利审核不因试点而取消。

## 资料边界与下一步

无需先开通官方 API，也不应把完整剧本、未授权素材、账号 Cookie 或游客个人数据放进 GitHub。需要渔岛内容负责人提供或确认：九九角色/世界观的权威版本、实际演出与可拍场景、素材权属和禁用表达、自有账号及一轮试点的目标（品牌认知、到场、票务或其他）。在资料到位前，可以先实现项目作用域、相关性隔离、选题卡和人工回填结构；不能凭模型自造“官方设定”。
